当前首版为 **v0.0.1 本地草案**。数据包与既有网页原型分开保存；封存数据不等于网站已经接入或上线。

目录有两个入口：**领域 → 细分赛道 → 具体工作**，以及 **职业大类 → 职业 → 职业任务**。每个节点有独立 ID，父子关系决定权重所在的分母，外部分类关联另存。一个外部代码可以关联多个自有节点；候选关联不会自动合并节点或传递进度。

职业入口完整覆盖 O*NET 31.0 的 23 个大类、1,016 个职业、18,838 条任务。O*NET 是美国职业参考，完整导入这份来源不等于完成全球或中国职业普查。全部职业都有 AI 中文翻译，英文原名与源代码保留；任务英文完整，任务中文仍为空。赛道目录采用自有中文词汇，并对照 ISIC Rev.5 全部 22 个门类记录覆盖。它是可迭代的广覆盖目录，不能宣称所有商业细分都已穷尽。

## 从事件到进度

一个工作项可以关联多条事件；一条事件包含多个指标观测。进度更新引用这些事件和观测，保存旧值、新值、估计方法、变化原因及时间。重复输入不重复形成增量；方法变化和证据变化分别记录。首版提供合同和校验器，自动估计器还没有实现，因此真实事件、观测、更新集合为空，初始进度均为 `null`。

关注指标、可用阶段、采用阶段、测试成功率、人工时间和成本分别定义。点赞与浏览不能独自形成能力进度更新。观测的 `0` 是实际零值；无法取得的值为 `null`，并记录缺失原因。父节点任何子项未知时，整体进度也未知，不剔除该子项后重新归一化。

## 权重起点

- 赛道的同级权重由 AI 提议，每条关系都附方法、理由和草案状态。
- 职业内任务的权重用来源 IM 重要性归一化。缺值或低精度值用本职业可用 IM 均值补齐；全职业没有可用 IM 时等分。
- 职业大类内的职业暂按等分。BLS 原工作簿已在本地，但尚未核验统计单元格并纳入权重。
- 没有将顶层领域强行凑成世界 100%。职业与赛道是两种视图，也没有相加形成统一世界总分。

IM 是对任务重要性的评级，归一化后只是初始代理，不能冒充工时份额、就业份额或经济占比。来源评级、推导基数和最终份额分开保存。原始本地资料不改写，导出时低精度 IM/RT 值留空并保留标记。

## 文件与来源

`source/` 保存本项目编辑的赛道目录及职业翻译；O*NET 和 ISIC 原始下载仍在 gitignored 的 `data/reference/`。`releases/vX.Y.Z/` 包含严格 Schema、JSONL 集合、可读目录和完整性清单。O*NET 引用保留出处并注明改编；ISIC 仅导出代码和层级，未获再分发确认的原文不进公开候选包。

主要集合是 `nodes`、`relations`、`weights`、`external_mappings`、`metric_definitions`、`events`、`observations`、`progress_updates`、`progress` 和 `sources`；`reference_*` 保留外部参考。字段定义以包内 [schema.json](releases/v0.0.1/schema.json) 为准。

## 校验与重建

```sh
pnpm platform:test
pnpm platform:check
pnpm check
```

首版生成器读取完整本地参考与两份编辑来源文件，核对数量、英文代码、中文覆盖、ISIC 门类及输入哈希后构建。默认目标存在时拒绝覆盖。要在本地复查生成过程，指定一个未使用的新输出目录：

```sh
pnpm platform:build --out=/tmp/openaiwill-v0.0.1-rebuild
```

这会使用相同来源生成同样的数据记录；构建时刻和其派生 manifest 哈希会改变，因此是可比较的重建副本，不是对已封存字节的替换。真实迭代必须按 [版本规范](VERSIONING.md) 构建新版本。
