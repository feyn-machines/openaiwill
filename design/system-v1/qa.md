# 设计交付检查

## 每次修改

1. `pnpm design:build` 后运行 `pnpm design:check`。修改项目代码另运行 AGENTS.md 中的 lint、typecheck 和 build。
2. 浏览器实际打开 `preview.html` 或业务页面，检查 1440 / 1024 / 390 / 320px。正文不横向溢出；复杂表格可局部滚动并有标识；重要图表有可读文字值。
3. 验证默认、悬停、键盘焦点、选中、禁用和错误反馈；键盘可操作所有控件；样本表单只作本地格式检查。
4. 检查 `prefers-reduced-motion`；动画只在用户触发后运行，完成后停止。所有内容在动画开始前已可读取。
5. 检查未知值与零、来源与宣称、估计与观测、情景与置信区间的区别。示例数字明确标为虚构。
6. 输入桌面/手机截图及参考图，按 `prompts/critic.md` 做独立审阅。前两轮解决最关键问题；评分不替代实际检查。

配色门槛采用 [WCAG 文本对比要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：正常文本至少 4.5:1，大文本至少 3:1。控件边界与必要图形按 3:1 检查；装饰网格不承担内容含义。数学配色校验只覆盖列出的组合，不代表整个页面通过无障碍认证。
