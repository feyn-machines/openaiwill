# 官方 X 账号采集

确认于 2026-09-13。这个入口修复了第一次两周采集中遗漏 OpenAI 重大公告的问题。当前只负责本地读取、保存与覆盖验收，不调度任务、不抽取事件、不写数据库、不发布网站数据。

## 为什么旧批次会漏帖

旧脚本把同一公司的多个账号合并为一次周范围搜索，每条查询只取一页、最多 20 条。OpenAI 本周查询的 20 条全部来自 9 月 11 日 UTC；同日的连续产品帖和回复占满结果，9 月 10 日 UTC 发布的 ChatGPT for Financial Services 没有进入结果。

旧补抓也没有使用 X 给该查询返回的原生分页游标。它从所有查询合并后的帖子中，按账号和宽日期范围重新寻找最小帖子 ID。相邻两个查询范围在 9 月 6 日 UTC 重叠，本周 OpenAI 补抓因此从 9 月 6 日继续，直接跳过 9 月 7—10 日。对旧档案的离线审计发现 26 条主查询中有 13 条触及 20 条上限，OpenAI、Google、Microsoft、Alibaba、Tencent、MiniMax 共 6 家公司的本周补抓边界被其他时间窗口污染。

旧批次正确标为 `partial`，但当时的验收只证明文件、引用、哈希和计算可复现，没有用已知重大公告检查来源覆盖。这就是测试全绿仍然漏掉关键材料的原因。

## 当前采集规则

`scripts/collect-official-x.py` 默认读取 `datasets/official-x-accounts.json` 中已启用且身份已确认的账号。每个账号在整个目标时间窗中只有一条独立任务，通过 X 的账号时间线读取普通帖和串内后续帖；不同公司、账号和窗口不共享结果额度或游标。

程序逐页保存原始 X JSON，再由项目自己的解析器读取，绕开 Twikit 对可选用户字段的脆弱对象解析。每页保存 SHA-256，规范化记录保留原帖 ID、作者及用户 ID、发布时间、正文、回复/转帖状态和互动快照。作者 handle 与注册用户 ID 必须同时匹配；时间使用 `[start, end)`，缺失互动值保持 `null`，实际零保持 `0`。

分页使用 X 原生 cursor。只有整页帖子都早于目标开始时间，或服务端不再给 cursor，才结束该账号；一页同时包含窗口内外材料时继续翻页。空页若仍带 cursor 会标记为 incomplete，不能冒充正常结束。所有账号都结束、没有身份/结构/请求错误，且所有 `--expect-post` 已出现，运行才返回成功。请求或解析一旦失败，本次立即停止，未执行账号保持 incomplete；不会把失败查询写成零更新，也不会轮换账号继续。

即使运行成功，覆盖含义也仅为“当前 X 响应中可见的注册账号时间线已翻过目标起点”。已删除、受限或 X 未返回的帖子仍可能缺失，所以重要发布还要和官网发布记录核对。

## 使用

输出必须是本项目根目录 `data/` 下一个尚不存在的 JSON 文件。文件、锁文件和逐页原始响应都留在本机，权限为 0600。

```sh
pnpm data:collect:x -- \
  --start 2026-09-10T00:00:00Z \
  --end 2026-09-11T00:00:00Z \
  --output data/collection/official-x/<new-run>.json
```

先查看计划、不访问 X：

```sh
pnpm data:collect:x -- \
  --start 2026-09-10T00:00:00Z \
  --end 2026-09-11T00:00:00Z \
  --plan-only \
  --output data/collection/official-x/<new-plan>.json
```

限定已经启用的账号，并设置已知公告验收点：

```sh
pnpm data:collect:x -- \
  --start 2026-09-10T00:00:00Z \
  --end 2026-09-11T00:00:00Z \
  --handles OpenAI \
  --expect-post 2098118191029624911 \
  --expect-post 2098118232133792050 \
  --expect-post 2098118249582035348 \
  --output data/collection/official-x/<new-openai-run>.json
```

入口沿用项目 `social-qingguo-collector` 的本地 X 登录状态和青果代理，遵守至少 3 秒的请求间隔。不会自动登录、重试、轮换账号或直连 X。再次执行必须换新输出名，旧运行不会被覆盖。

## 实际验证和剩余工作

2026-09-13 经青果对 `@OpenAI` 的账号时间线做了真实验证。目标窗口为 9 月 10 日 UTC，2 次请求翻过窗口起点，原始第一页返回 18 条可解析帖子，窗口内保存 6 条；ChatGPT for Financial Services 主帖和两条后续帖全部通过验收。旧归档中三条均缺失。

离线回归覆盖账号隔离、窗口不重叠、原生 cursor、账号公平分页、页/请求预算、已知公告缺失、身份错配、半开时间窗、零与缺失值、原始时间线解析、不可用帖子、游标循环、请求失败、部分状态、私有输出和不可覆盖运行。

尚未完成全部 51 个启用账号的真实窗口回补、官网发布记录自动对账、定时调度、自动事件提取、数据库新批次或重新估计。X 搜索接口在诊断期间出现过 HTTP 404，而账号时间线仍返回 HTTP 200；关键词搜索只作为后续发现通道。监控频率、代理流量、X 请求预算和长期成本应在完整账号试跑后按实际分页数估计。
