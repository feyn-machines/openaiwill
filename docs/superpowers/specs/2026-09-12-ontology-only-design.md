# openaiwill 独立本体实现

用户当前范围：先实现本体，其他先不动。工作、赛道、职业及其定义、分类和关联是本体；事件、指标和进度计算是后续业务运行模型。本轮不创建 Compose、PG 表或运行数据结构，不修改已封存 platform/v0.0.1。

## 输出

独立包位于 `datasets/ontology/releases/v1.0.0/`。它从已经完整校验的 platform/v0.0.1 提取本体部分，沿用所有概念与关系 ID，明确记录来源版本和 manifest 哈希。`1.0.0` 表示拆分混合合同后的结构版本，不表示语义已穷尽或已经上线。

包内有标准 JSON 的模型说明、JSON Schema 2020-12、JSONL 全量目录、可读目录、覆盖说明和不可覆盖的哈希清单。模型定义与实例目录分开；不引入 RDF/OWL 运行栈或图数据库。

## 本体合同

- 五种概念类型：`market_group`、`market`、`work`、`occupation_group`、`occupation`。模型说明逐一描述业务含义。
- `concepts` 保留原节点 ID、kind、中英文名称、来源、翻译/范围状态；增加可空的 `definition`，有来源职业描述、任务原文或已有编辑范围时直接引用。没有额外定义的条目保留 null 并统计，不能把新造的解释冒充已有来源。
- `relations` 保留原关系 ID、view、parent_id、child_id、order，增加语义明确的 kind：`has_market`（领域→赛道）、`has_work`（赛道→工作）、`has_occupation`（职业大类→职业）、`has_task`（职业→工作）。这些是组织/关联关系，不是任意 `is_a` 继承。各关系允许的两端类型与视图由模型声明并校验。
- 同一工作可被多个父节点或视图关联，不把职业任务与自定义工作按文字相似度合并；两个视图也不自动相加。
- `external_mappings` 用 `concept_id` 引用自有概念，保留外部体系、来源版本、代码、关联类型和候选/核验状态。候选关联不自动成为等价关系。
- 来源职业、任务、活动、任务活动关联和 ISIC 代码层级作为独立参考集合保留。任务参考仅保留身份、职业关联、任务文本、类型、来源版本；排除 IM/RT/频率、样本数等统计数值。职业参考排除任务计数。
- 来源仅包含实际引用的 O*NET、ISIC 和编辑目录出处；BLS 等未用于本体的输入不携带。保留许可说明，ISIC 仍只包含代码层级。
- 不包含 weights、events、metric_definitions、observations、progress 或 progress_updates；不修改旧实现。

## 可执行约束

1. 严格字段类型与 additionalProperties:false，错误混入运行字段/集合必须失败。
2. 概念、关系、映射和参考身份唯一；关系目标存在；同视图/父节点下顺序唯一；重复边被拒绝。
3. 关系 kind、端点类型和视图匹配。目录及外部活动/分类引用无环，父节点存在。
4. 外部代码、来源版本及任务/职业关联存在；AI 候选映射不能标成已核验。
5. 完整导出 23 个职业大类、1,016 个职业、18,838 项职业任务，以及 40 个领域、265 个赛道、614 项自定义工作；保留全部既有概念和关系 ID。
6. 验证 JSON Schema、模型说明、JSONL 行数、payload 哈希和清单自身哈希；拒绝未列入清单文件、非普通文件、篡改及覆写已有输出。

现有 O*NET 是美国参考；AI 中文职业翻译不是官方翻译；任务中文仍未翻译；部分概念只有名称，范围定义仍需完善。这些缺口随本体包明确记录。

本轮通过独立 ontology:test/build/check 命令和现有 pnpm check 完成验证，未请求 Git 提交、上传或部署。
