# 站点体验、可视化与白皮书 —— 设计规范 v1

状态：第一轮已实现，见第 10 节
日期：2026-09-22
适用版本：snapshot-1 / ontology 1.0.0 / semantic 2.0.0

本文件规定 openaiwill 网站的**体验逻辑、图谱可视化、进度表达和文案层级**，并把
[白皮书](../../whitepaper.md) 接入站点。视觉数值与组件规则的唯一来源仍是
[DESIGN.md](../../../DESIGN.md) 与 [design/system-v1](../../../design/system-v1/README.md)；
本文件不重新定义颜色和字号，只规定它们如何组织成一次阅读。

---

## 1. 诊断：现在为什么看不懂

以下均为对 `src/` 的实测，不是印象。

**1.1 站点里没有任何图。** `src/` 中的 SVG 只有一个 `icon.svg`（favicon，从不在页面里渲染）。
没有图表、没有流程图、没有节点连线、没有进度条，也没有任何图形依赖（`dependencies`
只有 `next`/`react`/`react-dom`）。最接近图形的是 `.oaw-status::before` 的 8×8 方块和
`/method` 里四个带编号的方框——后者没有箭头也没有连线。用户问「图在哪里」时没有答案，
是因为确实不存在。

**1.2 已确认的视觉方向从未落地。** `design/system-v1/` 里有完整的 Tensorlake 方向资源，
但 `src/` 中：

| 事实 | 实测 |
| --- | --- |
| `--ah-color-*` 使用次数 | **0**（颜色全部来自本地 `--bg/--ink/--muted/--line/--accent` 或裸十六进制） |
| 字体加载 | **无** `@font-face`、无 `next/font`，`"AH Inter Tight"`／`"AH JetBrains Mono"` 永远回退到系统字体 |
| 正文字体实际值 | **Arial / Helvetica** |
| 画布 | 浅色 `#f5f4ef`，而已确认方向是深墨色 `#161715` |
| 营销页（`/`、`/check`、`/domains`）token 使用 | **0** |

也就是说：规范包被验收过，网站没有用它。`design:check` 仍然通过，因为它校验的是
`design/system-v1/` 与生成文件，不校验 `src/` 是否引用。

**1.3 首页不读数据。** `src/app/page.tsx` 只引用 `src/lib/markets.ts`（历史原型的 20 个
编辑赛道），完全不 import `snapshot.ts`。品牌主张和证据体系是两个互不相连的半边。

**1.4 读者必须自己做连接。** 四类节点各有一个列表页（`/updates`、`/capabilities`、
`/occupations`、`/gates`），产品的主张「某次 AI 更新 → 改变你的判断」需要读者在脑子里
把四张表 join 起来。站点从未把这条链本身呈现出来。

**1.5 诚实被降级成脚注。** 18/46 能力没有证据、`reviewed = 0`、发布的是两个判断者里偏宽
的读数、证据由两套松紧不同的标准判出——这些是本项目最有价值的部分，现在都写在页面底部的
`Caveats` 段落里，以散文形式出现。

**1.6 其他实测问题。** `/check` 是孤儿路由（`src/` 中 `href="/check"` 零处）；
`/gates` 与 `/gates/[slug]` 没有 `DataPageLinks` 底部导航；站内共存三套 i18n 写法
（`t()` 字典、`bilingual()` 对象、行内三元）；没有 `loading.tsx`／`error.tsx`／`not-found.tsx`；
白皮书不在站点上。

## 2. 组织性想法：一条链，四个尺度

全站围绕**一条链**组织，它就是产品主张的可视形式：

```
AI 更新 ──→ 证据 ──→ 能力 ──→ 工作 ──→ 职业
                      ↑
                    闸门（挡住的部分）
```

这条链在四个尺度上重复出现，**图形语法完全一致**，只是焦点不同：

| 位置 | 焦点 | 链上显示什么 |
| --- | --- | --- |
| 首页 | 全局 | 整条链 + 每一环的实时计数 + 断口 |
| `/updates/[id]`（新） | 一次更新 | 这次更新证明了什么能力，或什么都没证明 |
| `/capabilities/[slug]` | 一项能力 | 什么证据支撑它 → 它触及哪些工作 → 哪些闸门挡着 |
| `/occupations/[code]` | 你的工作 | 你的工作依赖哪些能力 → 其中哪些有证据 |

### 2.1 最关键的一条：链要画出自己的断口

这是本设计的核心主张。**缺口不是脚注，是图形本身。**

| 数据事实 | 图形表达 |
| --- | --- |
| 能力有证据、有阶段 | 实线连接，实心方节点 |
| 能力无证据（18/46） | 连接**断开**，节点为空心虚线框，旁边写「无证据」 |
| 边为 `candidate`（全部 100,950 条） | 连接用 5px/5px 虚线，图例写「未经人确认」 |
| `reviewed = 0` | 链的最后一环「结论」**始终画成未接通**，并标注「需要人工确认」 |
| 能力过宽被搁置 | 节点移出主链，放进旁边的「已搁置」区，带 `requiring/judged` 两个数 |
| 证据由两套标准判出 | 证据节点分两种描边，图例说明哪一半更松 |

读者不需要读完段落才知道这套数据有多少没坐实——**看一眼链断在哪里就知道了**。
这同时满足 DESIGN.md 的约束：形状必须配文字，颜色不单独表达状态。

### 2.2 为什么不做一张全量力导向图

100,950 条边的节点图是一团毛线：读不出来、渲染慢，而且它会暗示一种这份数据并不具备的
精确度。**改为局部邻域视图**：以一个节点为中心，只画它的直接链路，上限约 30 个节点，
确定性布局（不做力模拟），服务端渲染成 SVG，零客户端 JS，不引入任何图形库。

代价是看不到全局拓扑。这是有意的取舍：全局拓扑目前没有可信的结论，画出来只会误导。

## 3. 进度怎么表达

站内有**三个互不相同的进度对象**，规定它们永不合并成一个数字：

1. **单项能力的自主阶段 0–4** —— `autonomy_stage` + `stage_status` + `limiting_factor`。
   按 DESIGN.md：数字旁明确写「估计」、范围定义、模型版本和时间。
2. **图谱覆盖度** —— 已判断 / 有证据 / 已人工确认，三级递减。第三级当前为 0。
3. **前沿** —— 最近这批更新推动了什么。

### 3.1 硬约束

- **不做全站 0–100 总分。** CLAUDE.md 明确禁止首页暗示"已实现的想法分析服务"或
  "可测量的创业失败概率"，且 `No production score is initialized`。
- `design/system-v1/assets/scenario-range.svg` 里的 `CENTRAL ESTIMATE 46.0 / 100`
  是标注为 `ILLUSTRATIVE / NOT LIVE` 的虚构样本，**不得挪用为任何真实数值的展示**。
- 情景区间不称统计置信区间。
- 阶段用阶梯（0–4 五格），不用百分比进度条——阶梯是序数，进度条读起来像比例。

## 4. 视觉落地：把已确认的方向接上

### 4.1 三项必须做的迁移

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 字体 | 从不加载，回退 Arial | 用 `next/font/local` 加载 `design/system-v1/fonts/` 的 Inter Tight 与 JetBrains Mono，保留 OFL 许可文件 |
| 颜色 | 0 处使用 `--ah-color-*` | 全站改用语义颜色变量，删除本地 `--bg/--ink/--accent` 一套同义色 |
| 画布 | 浅色 `#f5f4ef` | 深墨色 `--ah-color-bg: #161715`，信号绿 `#82c38c` |

**深色画布是本次最大的可见变化。** 它来自 2026-09-12 已确认的 Tensorlake 方向，
但此前从未落地，所以视觉上等同于一次改版。这一条单独列出，便于在评审时否决或推迟。

### 4.2 图形语法（沿用规范，不新增）

- 方形节点、直角转折、1px 细线、等宽标注、低对比网格背景。
- 来源记录＝实心方点；估计＝空心方点；待核验＝虚线；社区关注＝短线。
- 每种形状必配文字；颜色不单独承担状态。
- 品牌条带属装饰，`aria-hidden="true"`；流程图必须有 `<title>`、`<desc>` 和文字等价内容。
- 窄屏（<640px）复杂流程改纵向图形，参照现有 `evidence-flow-mobile.svg` 的做法，
  三个阶段的标题、说明和节点均可直接阅读，不得把横向图缩成缩略图。

## 5. 页面级规范

### 5.1 `/` 首页

保留品牌主张逐字不变：**Will AI Kill Your Idea?** / **Every AI update could change your answer.**
中文副标题：**每一次 AI 更新，都可能改变你的创业判断。**

结构（自上而下）：

1. **主张**——大标题 + 副标题，不加数据。
2. **链**——整条链的实时可视化，每一环带真实计数（当前：581 更新 / 158 证据 /
   46 能力 / 19,452 工作节点），断口按 §2.1 画出。
3. **两个入口**——「从你的工作开始」（职业检索）与「从最近的变化开始」（更新流）。
   **不提供"输入你的想法"输入框**：没有这个能力，做了就是暗示一个不存在的服务。
4. **本站现在说不了什么**——把 `reviewed = 0`、18 项无证据、偏宽读数三条提到首页，
   用链的断口图形呈现，不用段落。
5. 白皮书入口。

首页必须 import `snapshot.ts`。历史的 20 个编辑赛道从首页移除（`/domains` 保留为原型，
入口降级并标注为原型）。

### 5.2 `/whitepaper`（新增）

- 构建时读取 `docs/whitepaper.md`，按 `<a id="english">` / `<a id="zh-cn">` 锚点拆成两份，
  按当前语言渲染对应一份，另一份通过语言切换到达——不在同一页堆两种语言。
- 保留版本标注（v0.1 · 2026-09-13）与脚注编号。
- 白皮书把 openaiwill 定义为**倡议（initiative）而非平台**；页面文案不得把它写成平台，
  也不得把其中的设想机制说成已实现能力。
- 页脚与首页均提供入口。

### 5.3 `/updates` 与 `/updates/[id]`（后者新增）

- 列表保持时间流，但每条增加一列：**这次更新证明了什么**（能力名，或「未证明任何能力」）。
  当前 581 条里只有 121 条产生过证据，这一列会让这个比例直接可见。
- 详情页：链的一段——这条更新 → 它的证据层级 → 它支撑的能力 → 那些能力触及的工作。

### 5.4 `/capabilities/[slug]`

以该能力为中心的邻域图：左边是支撑它的证据（按层级），右边是它触及的工作与职业，
下方是挡住它的闸门。阶段用 0–4 阶梯显示，并标出 `limiting_factor` 是三道封顶中的哪一道。

### 5.5 `/occupations/[code]`

本轮已加入的「证据能覆盖这个职业多少」升级为图形：该职业依赖的能力排成一列，
有证据的接通、无证据的断开，一眼看出这个职业本站能说多少。
（实测：法务助理 14 有 / 6 无；超声技师 14 有 / 12 无。）

### 5.6 `/method`

保持为方法与诚实层的主页面，并接入 `docs/data/semantic-layer-journal.md` 里的方法修正记录
（16 条）——一条被推翻并改掉的判据，比一个正确结论更能说明数字该信到什么程度。

### 5.7 收尾项

- `/check`：并入首页的「本站现在说不了什么」区块，路由保留并从首页可达，不再是孤儿。
- `/gates`、`/gates/[slug]`：补 `DataPageLinks`。
- 新增 `not-found.tsx`、`error.tsx`，双语。
- i18n 收敛为 `bilingual()` 一种写法，逐页迁移；`t()` 字典与行内三元不再新增。

## 6. 文案层级

每个数据区块按固定三层写，顺序不变：

1. **这是什么**——一句话，不含术语。
2. **数字**——带单位，缺失写 `—` 并给原因，实测零写 `0`。
3. **这个数字的限度**——一句话说明它不能被用来做什么。

术语首次出现处给出定义，定义文本取自 `src/content/semantic-labels.json`（语义层投影），
不在页面里另写一套说法。

---

## 7. 不做什么

- 不做全站总分、不做失败概率、不做"输入想法"的分析入口。
- 不做全量力导向图。
- 不引入图形库（d3 / recharts 等），SVG 由服务端直出。
- 不把 `ai_proposed` 的边显示成结论，任何位置都不行。
- 不因为视觉需要而隐藏缺口——缺口是内容。

## 8. 验收

除 `pnpm check` 与 `pnpm data:test` 外，本轮另按
[design/system-v1/qa.md](../../../design/system-v1/qa.md) 执行：

1. `pnpm design:build` + `pnpm design:check`。
2. 实看 1440 / 1024 / 390 / 320px，`body.scrollWidth` 等于视口宽度，正文不横向溢出。
3. 中英双语逐页核对；英文为默认语言，浏览器语言不得静默覆盖。
4. 键盘焦点、`prefers-reduced-motion`、WCAG 对比（正文 4.5:1，大字 3:1，控件与必要图形 3:1）。
5. 图形有 `<title>`／`<desc>` 与文字等价内容；示例数字标为虚构。
6. 独立上下文截图审阅（`design/system-v1/prompts/critic.md`），前两轮只解决最关键问题。

## 10. 实现记录（2026-09-22）

本规范的第一轮已落地。以下为实测结果，不是计划。

### 已实现

| 项 | 规范节 | 结果 |
| --- | --- | --- |
| 字体真正加载 | §4.1 | `next/font/local` 自托管 Inter Tight 与 JetBrains Mono，OFL 许可随包保留。此前从未加载，正文实际是 Arial |
| 颜色接上 token | §4.1 | 两份样式表里 48 处裸十六进制按角色映射为 `--ah-color-*`，现在 `src/` 中裸十六进制为 0 |
| 深色画布 | §4.1 | 全站四个本地变量重绑到 token，一处切换整站。实测对比度：正文 17.08:1、muted 8.94:1、signal 8.68:1 |
| 链组件 | §2 | `src/components/evidence-chain.tsx`，服务端直出 SVG，零客户端 JS，无图形依赖 |
| 链画出断口 | §2.1 | 虚线＝机器提议未确认；断开带叉＝无证据或未经人确认；`reviewed = 0` 使最后一段恒为断开 |
| 首页重写 | §5.1 | 改为读快照数据（此前完全不读）。`/check` 并入「本站现在说不了什么」 |
| 白皮书上站 | §5.2 | `/whitepaper`，按锚点拆分，按语言只渲染一份，无新增依赖 |
| 更新流「证明了什么」 | §5.3 | 新增列与卡片：581 条更新中 104 条产生证据；空格子写理由而非留白 |
| 更新详情页 | §5.3 | `/updates/[id]`，含「这条更新没有证明任何能力」的正式区块 |
| 能力页链 | §5.4 | 复用同一组件。实测 clinical-observation：0 证据 / 无阶段 / 200 条工作边 / 198 个职业——断口直接可见 |
| 职业页阶段梯子 | §5.5 | `src/components/stage-ladder.tsx`。法务助理 6 项无证据，超声技师 12 项 |
| 收尾 | §5.7 | `not-found.tsx`、`error.tsx`（Next 16.3.4 已将 `reset` 降级、改推 `retry`）、闸门页补底部导航 |

### 按已确认方向自行决定的

- **深色画布**采用。它执行的是 2026-09-12 已确认的 Tensorlake 方向，不是一个新决定；可随时回退，四个变量改回即可。
- **`/domains` 降级**：移出主导航，路由保留。

### 仍未做

- 独立上下文截图审阅（§8 第 6 条）。对比度已按数值校验，实际观感尚未经第二人审阅。
- 1440 / 1024 / 390 / 320px 的实看与 `body.scrollWidth` 核对（§8 第 2 条）。链图放在 `overflow-x:auto` 容器内、最小宽度 900px，按设计应在窄屏内部滚动而不撑破页面，但未实测。

### 不在本规范范围

`reviewed` 仍为 0。它只能由人确认边之后改变，设计无法代劳。
