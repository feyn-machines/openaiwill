## 1. 设计简报与决定状态

### 用户明确给出的方向

- 首页要宏大、吸引人并留住人，让读者感受到整个世界正在因 AI 变化。
- 阅读顺序是「世界 → 时间线 → 赛道 → 职业 → 你」，从世界走向自己。
- 「世界正在因 AI 变化。」之后要有延伸问题，带读者继续探索。
- 文案应像沟通与对话，避免站在网站自身视角介绍功能。
- 重新判断设计、动效、信息传递、文案、品味和页面架构；旧页面布局不构成新方案的限制。

### 本文提出、尚未逐项确认的方案

- 五章共用一个持续变化的工作版图，随着阅读逐步聚焦。
- 事件选择贯穿赛道、职业；点击固定选择，滚动推进章节。
- 首屏工作版图、时间轴、关系高亮、证据抽屉与末章搜索的具体形式。
- 下文中英双语文案、标题落位和动效编排。
- SVG / D3 / GSAP 技术组合。

## 2. 页面架构与阅读路径

```text
世界正在因 AI 变化。
        ↓ 它究竟改变了什么？
时间线：变化落到具体的一次更新
        ↓ 它进入了哪些赛道？
赛道：更新关联到具体工作环节
        ↓ 这些工作，又由谁来做？
职业：变化关联到职业中的任务
        ↓ 那你呢？
你：选择自己的赛道或职业，进入详细答案
```

五章是同一段探索的不同尺度。工作环节作为更新、赛道与职业之间的解释节点嵌入第二至第四章，不另加第六章。非技术障碍放在相关环节或证据说明中。

导航保留品牌、Updates / Markets / Occupations 和语言切换；首屏主要阅读入口是进入变化，而个人搜索位于最后一章。白皮书与方法解释可从来源说明或页脚进入。

## 3. 视觉与品味

- **世界规模来自内容和空间。** 深墨色画布、宽留白、大标题与横贯画面的工作版图建立开场。大面积图形应有可读的数据含义。
- **同一张图逐步聚焦。** 工作单元、事件、赛道和职业保持实体身份，通过聚合、展开和连接改变关注尺度。采用稳定章节状态之间的转换；不强求把不同口径的数据几何变形成同一个比例图。
- **数据承担视觉中心。** 当前已有工作的状态与关联构成图形。宏大感不依赖无语义的球体、漂浮粒子或随机数字。
- **绿色表达当前信号。** 当前事件和关联路径使用信号色；其他内容退到背景。实体与状态同时有文字、形状或线型提示。
- **一章一个主要问题。** 正文、图形和操作回答同一个问题；来源与方法在可展开区域中提供。

复用 [DESIGN.md](../../../DESIGN.md)、[资源包](../../../design/system-v1/README.md)中的 `--ah-*` tokens、Inter Tight、JetBrains Mono、方形节点与细线。中文使用系统黑体。字体、素材许可与现有资源来源要求继续适用。

## 4. 对话式文案草案

下表是用于分镜的候选文案，英文也需随实际构图评审。标题旁的数值说明由真实数据生成。

| 章节 | 中文候选 | English draft | 应回答什么 |
| --- | --- | --- | --- |
| 世界 | 世界正在因 AI 变化。\n它究竟改变了什么？ | The world is changing with AI.\nWhat is actually changing? | 当前记录显示，哪些工作已有变化依据，哪些仍不清楚？ |
| 时间线 | 变化从哪一次更新开始？ | Where did the change begin? | 在已采集时间窗内，哪些具体更新关联到了工作？ |
| 赛道 | 它进入了哪些赛道？ | Which markets does it reach? | 所选更新关联了哪些赛道、哪些工作环节？ |
| 职业 | 这些工作，又由谁来做？ | Who does this work? | 这些工作关联到哪些职业与任务？ |
| 你 | 那你呢？\n你的工作，正在发生什么变化？ | And you?\nWhat is changing in your work? | 找到自己的职业或赛道，并进入具体任务与证据。 |

### 文案规则

1. 前一章留下的问题由后一章的数据回答。章节之间形成对话，避免堆叠口号。
2. 用「这次更新关联到……」「其中哪些环节已有证据……」描述记录；关联本身不证明真实替代已经发生。
3. 标明「已采集」「当前目录」「当前快照」等必要范围，避免把有限来源包装成全世界实时监测。
4. 避免以「我们为你展示」「平台通过……」作为章节开场。方法在读者需要解释时展开。
5. 末章可接回既有「Will AI kill your idea? Replace what you do?」品牌追问；不承诺系统能测出企业失败概率或个人失业概率。
6. 英文默认，中文完整提供；语言切换不改变数值、来源或选中实体。缺少译文时明确标注原文。

## 5. 五章分镜

### 01 世界：先让人感到规模，再提出问题

**画面**：大标题与一片覆盖宽画布的工作单元。前景是当前有证据的区域，背景保留证据不全与尚未涉及的区域。图例与范围说明位于图形边缘，可直接读取。

**数据**：当前目录的任务总数、L0–L5 分布，以及有证据 / 证据不全 / 尚未涉及三种覆盖状态。可用 100 格作为聚合表示，原始精确数量另以文字提供。

**交互**：聚合区域支持悬停或键盘聚焦查看定义与数量，点击打开状态说明或相关目录。聚合格不伪装成一项具体任务。

**动效**：标题立即可读；版图一次显现，随后稳定。滚动至下一章时，时间轴从同一画布的焦点区域展开。覆盖率不能被标成「世界被 AI 接管的百分比」。

### 02 时间线：把宏观变化落到一件事

**画面**：按时间排列的更新密度图与事件列表；明确显示采集时间窗。当前事件有一张可读摘要，图中标出它关联到的工作环节。

**数据**：去重事件、原始发布时间、来源组织、工作关联与证据状态。按日聚合的柱高表示更新数量，有工作关联的事件作为其子集单独标识。

**交互**：公司与事件类型筛选；悬停仅预览，点击或键盘确认后固定事件。初始不默认选中事件；用户选择后，该事件贯穿后续章节。没有选择也可浏览整体赛道和职业。

**动效**：选择后，一次短路径信号连接事件与工作环节。时间线停在可读状态，不自动轮播。仅当有同一方法下可追溯的前后状态时，才能表现等级真的前移；普通关联用连接高亮。

### 03 赛道：解释变化进入了哪里

**画面**：赛道总览与当前关联的一组工作环节。保留全局背景，强调所选事件相关的节点；右侧提供名称、环节与来源摘要。

**数据**：赛道、工作环节及事件关联；如提供「近期关联更新数」排序，写清去重口径与时间窗。活动数量和任务数量分别标单位。

**交互**：选择赛道后展开相关环节，点击进入 `/markets/[id]`。有事件选择时显示相关范围，并提供返回全局按钮。事件筛选不自动选定一个赛道。

**动效**：关注点转向相关赛道，其余内容降低强调。展开环节采用短状态转换；连线表示已有或待审关联，不声称事件造成了该赛道所有变化。

### 04 职业：从工作类别走向做这些工作的人

**画面**：职业大组的可读分布，选中大组后出现具体职业；所选事件或赛道的关联沿同一阅读路径延续。

**数据**：职业大组、职业、任务状态与已有映射。仅有赛道 → 职业映射时，标为「关联职业」；没有活动 → 任务的具体依据时，不声称某个职业任务已被该事件改变。

**交互**：职业组切换、职业搜索、进入 `/occupations/[code]`。没有可靠关联时显示「尚无可用的职业关联」，仍可查看完整目录。

**动效**：关联职业组依次获得焦点，文字同步出现。整个职业列表保持稳定，不让大量行随滚动不断进出场。

### 05 你：把探索交给读者

**画面**：「那你呢？」作为空间和语气的收束。下方提供职业 / 赛道切换与搜索；当前探索对象可作为快捷入口。

**数据**：现有职业和赛道目录，结果显示名称、类别及可用证据状态。

**交互**：选择结果进入现有详情页，继续查看具体工作、来源和非技术障碍。查询无需登录；首版不增加个人档案或想法分析表单。

**动效**：宏观版图退为安静背景，输入获得视觉焦点。搜索与结果使用即时反馈，读取答案不依赖动画结束。

## 6. 数据口径与展示适配

当前读取实现见 [src/lib/snapshot.ts](../../../src/lib/snapshot.ts)，首页服务端关联处理见 [src/app/page.tsx](../../../src/app/page.tsx)。以实际导出的只读数据和对应合同为准。

| 展示内容 | 当前数据入口 | 显示约束 |
| --- | --- | --- |
| 快照身份、更新时间、版本和限制 | `manifest` | 生成时间与事件发布时间分别显示；读取实际存在的字段 |
| 目录任务规模、三态与等级分布 | `progress` | 任务分母保持一致；圆整后 100 格应守恒；精确数值单独保留 |
| 更新数量、时间与筛选 | `events` / `chainEvents` | 全部更新和有工作关联的更新分开；采集范围不等于世界事件总量 |
| 事件关联工作与赛道 | `evidence` + `activities` | 保留实体 ID、证据状态、等级与范围；来源宣称和记录等级不混用 |
| 赛道关联职业 | `marketEdges` + `progress.groups/occupations` | 一般关联与具体任务影响分别表达；多对多映射不能跨视图相加 |
| 限制与来源 | 来源 URL、证据状态、`gates` | 非技术障碍解释具体环节；厂商来源不等于独立验证 |

### 数据边界

- 本规格不硬编码讨论时的快照数量。所有标题数字、比例和图形取自同一有效版本，更新数据时不用修改文案文件。
- 未知、未涉及和实测零保持不同状态。缺失快照显示空状态，不生成演示数据充当发现。
- 时间线表示事件发生顺序。当前状态快照不能推导出历史进度曲线；没有前后可比记录时，只展示关联路径。
- 任务状态的分布不表示就业人数、经济份额或失业风险。没有相应权重与方法时，不绘制这些比例。
- 默认标明「机器提议，未经人工确认」等实际状态；部分经过核验时按记录分别显示，不能整体升级为已验证。
- 服务端整理页面需要的聚合与关联，浏览器接收适量的可序列化视图数据。数据缺失不触发网页采集或重新评分。
- 现有页面从已导出快照读取。本次 UI 设计不决定此前独立的线上数据库/API 迁移方案。

## 7. 交互状态与证据抽屉

| 状态 | 进入方式 | 行为 |
| --- | --- | --- |
| 全局 | 首次进入、重置选择 | 五章展示当前整体快照 |
| 预览 | 悬停或键盘聚焦实体 | 临时说明，不覆盖固定选择；移开恢复 |
| 事件已选 | 点击或键盘确认事件 | 固定事件 ID；后续高亮其已有关系 |
| 赛道 / 职业已选 | 确认节点或搜索结果 | 展开该对象；可进入详情页；切换上游时清除不再相关的下游选择 |
| 来源展开 | 点击证据入口 | 抽屉呈现来源、日期、支持内容、核验状态与限制 |
| 无关联 / 无结果 | 数据确实缺失或筛选无匹配 | 说明范围与原因，提供返回全局或修改筛选入口 |

**滚动只改变章节和视觉关注，不更换固定事件、不改写数据。** 展开来源时保持当前选择和滚动位置；关闭后返回原触发元素。桌面侧抽屉、手机全宽面板均支持键盘访问、关闭与焦点管理。

同一段关联高亮可以重放，但不自动循环。图形按钮有可访问名称，所有悬停信息也能通过点击或键盘获得。

## 8. 动效编排与制作方式

### 动效职责

| 动作 | 驱动 | 视觉变化 | 结束状态 |
| --- | --- | --- | --- |
| 开场 | 一次进入 | 工作版图显现，建立整体空间 | 标题、图例与数据稳定可读 |
| 章节转换 | 原生滚动进度 | 画布焦点、聚合尺度、章节强调变化 | 停留时完整表达本章 |
| 事件关联 | 明确选择 | 方形信号沿已有关系路径移动 | 对应节点高亮，无持续闪烁 |
| 赛道 / 职业展开 | 点击或键盘确认 | 局部位置、透明度与边界变化 | 名称、状态和操作稳定 |
| 抽屉 / 搜索反馈 | 用户动作 | 简短状态转换 | 即时响应、焦点清晰 |

即时反馈、状态切换、显现与完整路径演示分别使用现有 `motion-feedback`、`motion-transition`、`motion-reveal`、`motion-sequence` tokens。滚动编排用阅读进度控制，不把固定时间当成必须等待的阅读时长。

### 技术分工（建议，未安装）

| 层 | 建议 | 责任 |
| --- | --- | --- |
| 页面 | 现有 Next.js App Router / React / TypeScript | 服务端生成内容，客户端管理选择与浏览器交互 |
| 图形 | React 渲染 SVG | 聚合格、坐标、节点、路径与可读标签 |
| 几何计算 | `d3-scale`、`d3-shape` | 数据尺度与路径计算；不直接操作 React 管理的 DOM |
| 章节编排 | `gsap` + ScrollTrigger + `@gsap/react` | 原生滚动进度、局部固定与 timeline；组件卸载清理 |
| 微交互 | 现有 CSS / CSS Modules | 按钮、焦点、搜索反馈和简单状态转换 |

当前 `package.json` 的产品依赖只有 Next.js、React、React DOM。已有 [reveal.tsx](../../../src/components/home/reveal.tsx)与 CSS 原生动效需在实施时明确替换或保留，不让两个系统同时控制同一元素。

React 状态决定数据与选择，GSAP 只编排视觉变化。固定展示外层可以保持稳定，内部图层进行变换；文字与交互区域保留正常滚动和阅读。首版不叠加多个完整动画引擎。

先用聚合 SVG。只有确实需要大量独立标记、且实测 SVG 有性能瓶颈时，再把该标记层换成 Canvas；标签与控件仍保留在 DOM 中。Three.js、整页 Lottie 和循环视频不作为本版核心依赖。

技术参考：[GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)、[GSAP React](https://gsap.com/resources/React/)、[D3 scale](https://d3js.org/d3-scale)、[D3 shape](https://d3js.org/d3-shape)。这些是方案依据，不代表本项目已集成。

### 制作顺序

1. 画出五章静态关键画面，包括正常、无数据和选择状态；同时准备英文、中文、桌面和手机构图。
2. 使用真实内容长度和有效快照制作可点击片段，打通事件 → 工作 → 赛道 → 职业与来源展开。
3. 内容和选择行为成立后，增加章节滚动编排和一次关联演示。
4. 在浏览器检查移动端、键盘、减少动态效果与性能，再扩展完整页面。

## 9. 手机、无动画与失败状态

- 手机使用纵向章节、可读列表与点按展开；关系图可聚合为逐步连接的文本和节点。避免把桌面长时间固定的画布直接缩小。
- 控件至少 44px；复杂图形有文字摘要和同等信息入口。状态不只靠颜色区分。
- `prefers-reduced-motion` 下直接呈现各章静态结果，取消视差、长位移和滚动跟随变换。所有选择、来源与搜索功能继续可用。
- 无 JavaScript 时，标题、说明、数据摘要、详情链接和来源仍可读取。交互动画加载失败时不隐藏主要内容。
- 无快照时展示明确空状态与目录入口；无事件关联时保留时间线；无职业关联时允许浏览职业目录。
- 不同快照版本不混合渲染。数据更新时稳定展示一个版本，更新时间与版本说明同步变化。
