状态：待评审

本文取代 [页面架构](2026-09-22-page-architecture.md) 中关于数据读取方式的部分，
路由部分继承并扩充。方法与管线见
[能力词表与管线设计](2026-09-22-capability-vocabulary-and-pipeline-design.md)。

---

## 一、五个已确认的决定

用户于 2026-09-22 逐条确认：

1. **首页动效是滚动驱动的**，不是仅用户触发。这与 DESIGN.md 现行「阅读区域不持续
   闪动」冲突，DESIGN.md 随本设计修订（见第七节）。
2. **首页的叙事从事件起头**：刚发生了什么 → 它打到了哪些工作 → 那些工作属于哪些
   赛道 → 属于哪些职业 → 全局比例 → 为什么还卡着。
3. **能力层从 UI 全部删除**。46 个能力里 41 个匹配一切，它算出的数字是错的；留着
   页面等于邀请读者去用已经作废的结论。
4. **schema 与数据严格分界**：类型只在语义层，实例只在 PostgreSQL。
5. **前端对接数据库 + API，不读文件**。JSON 快照降级为版本化存档与校验批次。
   部署在自己的独立服务器上，不使用 Vercel。

## 二、数据与 schema 的分界

### 2.1 当前的违反

层级封顶（T1→5 T2→4 T3→2 T4→1）这一条规则，现在有四份拷贝而没有一个是出处：

| 位置 | 形态 |
| --- | --- |
| `rule:tier-caps-stage.expression.cap_by` | 指向 `evidence_tier.stage_cap` —— 但那里没有值 |
| `rule:tier-caps-stage.currently_lives_in` | 指向 `datasets/scoring/method.v0.json` |
| `activity_state.py` | `TIER_CAP = {"T1": 5.0, ...}` |
| `publish.py` | SQL 里手写 `CASE ae.evidence_tier WHEN 'T1' THEN 5.0 ...` |

更严重的一处：`autonomy_stage` 词表只有 5 个词条（0–4），`scale` 写着「0-4，允许 0.5
步长」。**L5 根本不在类型层里**——它只活在 `event_routing.py` 的 `LEVEL_SCALE` 和
`work-grid.tsx` 的中英文文案里。一个新刻度被加进了系统，却没有加进声明它的地方。

### 2.2 类型层的改动

`datasets/semantic/semantic-model.v2.json`，可封存，无实例、无日期、无计数。

| 改动 | 内容 |
| --- | --- |
| `autonomy_stage` | 5 → 6 个词条，`scale` 改 `0-5`。L5「全场景独立交付」永久存在且当前为空——一个空的最高档是这张图最重要的一行，它必须在刻度里而不是在注释里 |
| `evidence_tier` | 每个词条增加 `stage_cap`：T1→5 T2→4 T3→2 T4→1。这正是 `rule:tier-caps-stage` 的 `expression.cap_by` 指向的位置；同时删除 `currently_lives_in` |
| 退休 `rule:breadth-limits-discrimination` | 能力层删除后无判定对象。标记 `retired` 并写明理由，不删除——一条被废止的规则是方法史的一部分 |
| 退休 `rule:blocked-by-needs-source-task` | 闸门改挂活动而非任务。同上标记退休 |
| 新增 `rule:task-level-is-the-minimum` | 一项任务的等级取覆盖它的活动里最低的一个。任务要全部做完才算做完 |
| 新增 `rule:three-states-are-not-zero` | 已评估 / 未知 / 未触及分开计数，后两者都不是 0 |

后两条现在只活在代码注释里。注释说服不了下一个改代码的人。

### 2.3 渲染层：一处生成，三处消费

```
semantic-model.v2.json
   ├─→ 判官 prompt 的 L0–L5 量表        现在 event_routing.py 硬写
   ├─→ SQL 封顶的 CASE                  现在 publish.py 手写数字
   └─→ 快照的 levels[] 与 tier_caps     现在 work-grid.tsx 自带中英文
```

前端不再自带一套级别名称——那是类型层被复制进了组件。

### 2.4 守门

`pnpm semantic:check` 增加两条扫描，与已有的「`derived_content` 不得回来」
「不得出现带日期的键」同一类：

- 封顶数值不得出现在 `.py` / `.sql` / `.tsx` 中；
- L 级标签文字不得出现在组件中。

## 三、发布链路

```
本地 PostgreSQL          唯一写入处。采集、抽取、判断、评审全在这里。
   │                     127.0.0.1:7543，密码文件 0600，整个 data/ 在 git 之外
   │  publish.py
   ▼
datasets/published/<批次版本>/     版本化 JSON 快照
   │                     只读构建产物，带 content_sha256。它是存档，也是
   │                     SECURITY.md 说的「经校验的导出批次」
   │  import.py（publish 的逆操作）
   ▼
线上 PostgreSQL          窄的只读副本，自部署独立服务器
   │                     没有任何写路径：不采集、不判断、不评审
   │  Server Component 直连 / Route Handler
   ▼
前端                     ISR，失效键是批次版本
```

**本地库不上线。** 19 个迁移里绝大多数是采集与判断的运行时——`collected_sources`、
`collected_captures`、`judgment_runs`、`judgment_items`、`judgment_checkpoints`、
`extraction_runs`。它们是产生结论的过程而不是结论，而且带着账号、游标、原始抓取这些
按 CLAUDE.md 必须留在本机的东西。

**快照文件不是第二个数据库。** 它按页面需要切，不按表切。10 个文件减到 4 个：

| 文件 | 内容 | 服务谁 |
| --- | --- | --- |
| `manifest.json` | 批次版本、`content_sha256`、生成时间、采集窗口、caveats | 溯源与导入校验 |
| `progress.json` | 全局 / 23 组 / 923 职业 / 251 赛道 的 L0–L5 与三态，加 `levels[]` 与 `tier_caps` | 第③④⑤屏、职业页、赛道页 |
| `chain.json` | 256 条有证据的事件 → 710 条证据 → 614 个活动 → 506 条闸门边 | 第①②⑥屏、赛道详情 |
| `events.json` | 581 条更新 + `source_urls` | `/updates` |

删除 `capabilities` `impact` `tasks` `gate_tasks` `gates` `evidence` `coverage`。
前五个属于能力层；后两个折进 `chain` 与 `manifest`。**13MB → 约 1MB。**

`chain.json` 是一个文件而不是三个，因为第①②屏读的是**一条链**，不是三张表。活动标签
与闸门边是这条链上的节点属性，不是独立实体。

## 四、线上库

七张表，约 1MB，schema 由页面需要决定而不是由本地表决定。

```
published_batches   批次：版本、content_sha256、生成时间、采集窗口、状态
work_progress       全局/职业组/职业/赛道 的 L0–L5 与三态计数
activities          614 个活动：标签、所属赛道、L 级、证据层级、证据数
evidence_chain      710 条：事件 → 活动 → L 级 → 层级 → 置信度
activity_gates      506 条闸门边
events              581 条更新 + 源头 URL
scale_terms         从语义层投影的 L0–L5 与 stage_cap（类型层在线的唯一副本）
```

每张表带 `batch_id`。**导入是插入新批次而不是覆盖**：旧批次留着，
`published_batches.status` 决定哪一批在线。回滚因此是改一行状态，不是重跑导入。

导入的硬约束照搬本地那套：幂等、校 `content_sha256`、批次不完整不得成为读取源。
校验不过的批次仍然入库，状态为 `rejected`，永远不会被 API 选中——一次失败的导入
留下记录，比留下空白更有用。

连接串走服务器上的环境文件（0600，不进仓库），**绝不进 `NEXT_PUBLIC_`**。

```
/                    事件 → 工作 → 赛道 → 职业 → 全局 → 闸门
/markets             251 个赛道对比                      新增
/markets/[id]        一个赛道：它的活动、证据、职业        新增
/occupations         923 个职业（找人）

/whitepaper          全部方法与弯路
/about               短页：这是什么 + 出口
```

删除 `/capabilities/[slug]`（能力层作废）与 `/updates/[id]`（`source_urls` 已在快照
里，读者应当直接回源头，而不是看我们多说一句）。

923 个职业页 + 251 个赛道页改 ISR，失效键是批次版本；新批次上线触发一次按需重验证，
不是每次请求都查库。

## 六、首页六屏

`prefers-reduced-motion` 与 JS 关闭时，**每一屏都渲染为它的动画终态**。DOM 先完整，
动画只是揭示。实现是 CSS keyframes + 一个 IntersectionObserver，不引入动画库。

时长全部取自 token，不自造数值：
`feedback 140ms` · `transition 240ms` · `reveal 600ms` · `sequence 1800ms` ·
`ease-out cubic-bezier(.22,1,.36,1)`

**播放规则**：第①⑤屏**跟随滚动位置**（scrub，双向连续）；第②③④⑥屏**进入播一次，
向上滚不回放**。回放会让页面在反复滚动时持续闪，那正是 DESIGN.md 要禁的；而 scrub
的两屏双向连续，不存在闪。

### 第①屏 · 最近发生什么

**数据** `chain.json` 中 256 条产出过证据的事件。另外 325 条沉默事件不在这屏，
它们属于 `/updates`。

```
2026-08-24 ────────────────────────────────────── 2026-09-20
    ○   ○ ○    ○  ○○   ○    ○ ○○  ○   ○○ ○  ●
                                            ↑ 默认选中
┌────────────────────────────────────────────────────┐
│ 09-20 · Alibaba                                    │
│ Qwen-Image-2.1 image generation model released     │
│ 打到 6 项工作 · 跨 2 个赛道 · 最高 L3 · 证据 T3    │
│                                        看源头 ↗    │
└────────────────────────────────────────────────────┘
```

**动效**

1. 轴线从左向右画出，`reveal 600ms`，**跟随滚动位置**。轴本身就是时间，让它跟着
   滚动推进是同一件事的两种表达。
2. 事件点按日期先后落下，每点 `feedback 140ms`，错开 24ms，总时长封顶
   `sequence 1800ms`。点为 6px 方形——图形语法用方端点，不用圆。
3. 卡片在轴画完后淡入，`transition 240ms`。

**交互** 悬停任一点换卡片（`feedback 140ms` 交叉淡）；点击锁定，第②③屏同步重算。
默认选中最近一条命中活动数 ≥3 的事件。

**出口** 「看源头 ↗」直达 `source_urls[0]`，多源时展开全部；「全部 581 条 →」通
`/updates`。

**移动端** 轴改纵向，卡片贴在选中点下方。

### 第②屏 · 它打到了哪些工作

**数据** `chain.json` 中该事件的证据行。默认事件命中 6 项。

```
                    ┌→ 生成场景概念图与背景画面      L3  T3
                    ├→ 制作绘画雕塑与装置作品        L3  T3
  ● Qwen-Image-2.1 ─┼→ 制作材质贴图与资产外观        L3  T3
    09-20 Alibaba   ├→ 制作角色立绘与角色设定图      L2  T3
                    ├→ 构思艺术主题与创作方案        L2  T3
                    └→ 实现工具调用与智能体工作流    L2  T3

  T3＝厂商自证，封顶 L2。三项判到 L3 的，发布值仍是 L2。
```

**动效**

1. 连接线从左侧节点向外画，每条 `transition 240ms`，错开 80ms，按 L 级从高到低。
2. 线到位后 L 徽标 0 → L 滚动计数，`transition 240ms`。
3. **层级徽标 T3 全程静止。** 它是封顶的原因；让它也动会暗示它是个在增长的量。

**这屏最重要的是最后那句话。** 判官判到 L3、发布值是 L2，差额来自 T3 封顶——这是整套
方法最容易被误读的地方，必须在 L 级第一次出现的地方就说清，而不是塞进白皮书。

**出口** 活动名点进 `/markets/[id]` 并锚到该活动。

### 第③屏 · 这些工作属于哪些赛道

**数据** `progress.json.markets`。只画第②屏命中的赛道。

```
游戏美术与资产生成     ▓▓▓▓▓▓▒▒▒░░░░░░░░░░░░░░░░   L2+ 41%
美术与独立艺术创作     ▓▓▓▓▒▒▒▒░░░░░░░░░░░░░░░░░   L2+ 28%
────────────────────────────────────────────────
全部 251 个赛道 →
```

每条是 25 列 × 4 行 = 100 格，与第⑤屏全局格子同尺寸、同顺序（`DRAW_ORDER`），
两屏因此可以直接比。

**动效** 格子条从左向右扫过，`reveal 600ms`，条间错开 60ms；百分比同步滚动计数。

**出口** 条目通 `/markets/[id]`，末行通 `/markets`。

### 第④屏 · 属于哪些职业

**数据** `progress.json.groups`（23 组）。小倍数，**全部画出**——这屏给的是格局，
不是这条事件的余波。

第②屏命中的赛道所对应的职业组高亮，其余降到 `color-subtle`。高亮不独占信息：行首
同时加一个实心方点（颜色不单独表达状态）。

**动效** 23 条同时扫开，`reveal 600ms`，按 L2+ 比例从高到低错开 20ms
（23 × 20 = 460ms，落在 sequence 内）。

**出口** 每组通 `/occupations/g/[id]`，末行「找你自己的职业 →」通 `/occupations`。

### 第⑤屏 · 全局

**数据** `progress.json` 顶层。

```
             这 100 格里，只有 6 格被评估过。
             其中 3 格 AI 已经出主体，人只做复核。
             没有一格做到全场景无人。

  ▣▣▣▤▤▤ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░

  27 格未知——这项工作里有一环没有任何方向的证据。
  67 格从没被采集到的更新提到过。
```

**动效** 格子按 `DRAW_ORDER`（L5→L0→未知→未触及）逐个填色，**跟随滚动位置**：滚到
这屏顶端是 0 格，滚到底部是 100 格填满，`6` 随之滚动计数。

选 scrub 而不是自播，是因为这屏的内容就是「填了多少」——绑在滚动上，读者是在用滚动条
量这件事。

### 第⑥屏 · 为什么还卡着

**数据** `chain.json` 中 506 条活动闸门边，10 道闸门有边。

```

手部灵巧      ██████████                110
工具使用      ██████                     62
医师签字      ██                         23
款项处置权    ██                         23

动物处置      ▌                           8

支付处理      ▏                           3

闸门不随模型变强而解除。被闸门约束的活动停在 L0——
```

### 收尾

```
机器提议的估计，尚未经人确认 · 采集窗口 2026-08-24 → 09-20
方法与全部弯路 → 白皮书        源码与数据 → GitHub
```

首页**不解释方法**。所有「为什么这么算」去白皮书，所有「怎么算的」去 GitHub。

## 七、DESIGN.md 的修订

现行条文：

> 演示需用户触发并可重放，阅读区域不持续闪动。

改为在首页开一个有边界的例外，而不是撤销这条规则：

> 首页允许滚动驱动的揭示动画。每屏进入播一次，向上滚不回放；跟随滚动位置的只限
> 时间轴与全局格子两处，且双向连续。其余页面维持用户触发。所有动画在
> `prefers-reduced-motion` 下呈现为终态，内容先于动画存在。

边界是「播一次」和「只限两处 scrub」。没有这两条，例外就等于撤销。

## 八、执行顺序

三个可分别交付的阶段。每个阶段结束时站点都是可用的——这不是把一件事切成三段，
而是三件事，后一件依赖前一件的产出而不是它的中途状态。

**阶段 A：语义层与发布**（1–2）站点仍读文件，但读的是新口径的 4 个文件。
**阶段 B：线上库与前端数据层**（3–4）站点改为查库，页面内容不变。
**阶段 C：页面**（5–7）删旧页、首页六屏、赛道轴。

1. 语义层：补 L5、补 `stage_cap`、退休 2 条规则、新增 2 条规则；`semantic:check` 加
   两条扫描。**先做这一步**，因为下面每一步都要从它读数。
2. `publish.py`：改为发布 4 个文件，封顶从语义层读，删除能力层导出。
3. `import.py` 与线上库迁移：7 张表、批次表、校验与回滚。
4. 前端数据层：`snapshot.ts` 由读文件改为查库；页面改 ISR。
5. 删除 `/capabilities/[slug]` 与 `/updates/[id]`，`/about` 缩为短页，解释迁入白皮书。
6. 首页六屏：结构与静态终态先落地，动效后加——动画是增强，不是前置条件。
7. `/markets` 与 `/markets/[id]`。

## 九、风险

- **线上库是新子系统。** CLAUDE.md 记录的一期范围不含它。Next.js 自己的 Route Handler
  查库不算独立后端，不与「不引入 FastAPI」冲突；但导入流程、批次管理、部署是新增工作，
  比「UI 重新布局」大。用户已确认要做。
- **1,000 个静态页改 ISR** 会改动每一个页面文件，不只是首页。构建期同步读文件的
  10 个模块级常量全部要变成异步查询。
- **滚动驱动动效与可读性的张力真实存在。** 边界写在第七节，实现时若发现读数据受干扰，
  应当收紧边界并记录，而不是留着。
- **采集偏斜没有被这次改动触及。** 13,049 项任务未触及的根因是采集窗口只有三周且严重
  偏向阿里与谷歌；页面必须把这一条放在显眼处（第⑤屏与收尾行），不能让读者把「没采到」
  读成「AI 做不到」。
