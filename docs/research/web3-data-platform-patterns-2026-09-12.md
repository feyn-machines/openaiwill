# Web3 数据产品：结构与可信表达研究

研究日期：2026-09-12。范围：DefiLlama、Dune、Nansen、Artemis、Token Terminal。本文研究真实数据产品的信息结构、图表与筛选、比较方式、来源和新鲜度表达，为 WillAI / AgentHowTo 的设计方向提供依据。

## 研究边界

- **页面事实**：本轮公开网页阅读器直接返回的导航、文案、表格和控件名称。
- **官方文档事实**：产品自己的帮助中心、API 文档、更新公告描述的功能；未实际操作不等于已经验证交互。
- **设计建议**：从这些模式迁移到 AgentHowTo 的判断，不是被参考网站对本项目的背书。
- 本轮没有使用浏览器截图，也未登录任何平台。因此不判断本轮未见的字体、颜色、间距、动效和响应式表现。营销首页上的演示图、宣传语和客户证言，不作为生产数据正确性或完整产品体验的证据。
- 搜索索引可能保留旧版文档。下文记录当前可取得的来源和已观察到的跳转；尤其不能把 Artemis classic 文档、Nansen 旧版教程当成当前应用的逐像素规范。

本文迁移建议依照研究时工作区的[当前进度框架](../data/takeover-progress-framework-v1.md)：**v0.2「事件与社区信号」**，冷启动展示原始信号与覆盖，尚未冻结归一化与权重；累计事件贡献与最近窗口热度分开。v0.1 的 A/R/U/D 人工四级评估已不再作为首版计分前置条件。该框架及实现状态应以工作区后续变更为准。

## 二、DefiLlama：从全局指标进入榜单，再下钻具体对象

### 已核实事实

1. **实体与指标并行组织**：公开页提供 Chains、Categories、协议排名，以及 Fees、Revenue、Volume 等指标入口。页面包含关键指标、1d / 7d / 1m 变化列、协议名称搜索、Columns、TVL Range 与 CSV 控件。比较是明确入口，而非只允许用户逐页阅读。[公开数据首页](https://defillama.com/)（访问：2026-09-12）
2. **比较对象显式选择**：Compare Protocols 页面有对象选择框，并提示至少选择两个协议。URL 可以包含被比较协议参数。[协议比较](https://defillama.com/compare-protocols?protocol=Curve+DEX&protocol=Sky+Lending)（访问：2026-09-12）
3. **同名指标需要业务定义**：Data Definitions 分别解释 Fees、Revenue 等口径；Expenses 明确主要来自年度报告，不是实时资料；Events 被定义为人工整理的解释性事件，帮助理解指标变化。[指标定义](https://defillama.com/data-definitions)（访问：2026-09-12）

### 迁移建议

- 总览以**市场行**为主：市场名称、观察到的事件数、近期讨论信号、覆盖状态、最近采集时间。已具备计算口径之后，再加累计贡献与窗口变化；不能先画满分排行再补数据。
- 市场、公司、产品是不同实体入口；声量、互动、参与广度是不同指标入口。它们可以相互切换，避免将网站整理成一串新闻卡片。
- 图表上的事件标记应能打开原始公告与变更解释。同一曲线上的跳变可能来自新事件、计数更新、归属修订或范围变化，要展示具体原因。
- 将「指标释义」和「报告数据问题」放在图表附近；来源、排除项、延迟限制不能只藏在页脚。

### 适合 / 不适合借鉴

**适合**：可扫描的榜单、短时间窗对照、列筛选、比较入口、指标旁的口径解释。**不适合**：照搬数十项导航、代币价格式红绿涨跌、把所有量压成一个排名。AI 事件的高热度可能来自事故与争议，不能因为数值增长就标成能力利好。

## 三、Dune：图表、解释和可复查查询构成同一份分析

### 已核实事实

1. **Dashboard 是组合分析单元**：由可调整大小的可视化和文字 widget 组成，图表从查询结果加入 dashboard。文本与图表共同说明一个问题。[Build Dashboards](https://docs.dune.com/web-app/dashboards)（访问：2026-09-12）
2. **刷新有明确触发条件**：该文档明确 dashboard 不是自动更新，可通过 Run 或排程刷新。嵌入图表随底层查询重新运行而更新；「嵌入可更新」不等于「数据永远实时」。[Dashboard 刷新](https://docs.dune.com/web-app/dashboards)、[Share and Embed](https://docs.dune.com/web-app/share)（访问：2026-09-12）
3. **参数是分析上下文**：可按地址、类别、日期等筛选，支持单选和多选；设置一致的参数可以跨多个查询共享，只在 dashboard 中出现一次。参数值也能写进查询描述。[Using Parameters](https://docs.dune.com/web-app/query-editor/parameters)（访问：2026-09-12）
4. **复查有专门入口**：Query Editor 文档包含数据目录、schema、查询版本历史、结果排序、CSV、排程和依赖关系等功能。作者工作区与读者 dashboard 的能力应分开理解。[Query Editor Overview](https://docs.dune.com/web-app/query-editor)（访问：2026-09-12）

### 迁移建议

- 赛道详情采用「一张主趋势图 + 一段解释 + 下方原始记录」；图表旁解释当前筛选范围、指标含义和有代表性的事件。
- 市场、时间窗、来源平台、覆盖配置、计算版本作为共享筛选上下文。改变一个参数时，相关表格、图表与解释统一更新，并能复制链接。
- 让周报引用固定快照或已发布版本；探索页面可以继续变化，已发布周报的历史依据应可还原。
- 将来源发布时间、采集时间、提供方计数更新时间、计算快照时间分开。没有可靠计数更新时间时，明确显示未知。

### 适合 / 不适合借鉴

**适合**：解释与图表并置、可分享筛选上下文、快照/查询溯源、对刷新状态的诚实表达。**不适合**：把普通读者首页做成 SQL IDE；照搬社区自由排版而失去统一层级；未经数据链路验证就加跳动的 LIVE 标记。

## 四、Nansen：先给可理解的对象标签，再沿关系逐层下钻

### 已核实事实

1. **围绕对象建立分析页**：Token God Mode 教程将代币概览、交易所流动、持有人和盈亏等分析集中到同一对象下；部分分析可切换 24h、7d、30d 等窗口。该教程标注已存在一年以上，本轮不将其当作最新布局截图。[Token God Mode 101](https://academy.nansen.ai/help/articles/3874203-token-god-mode-101)（访问：2026-09-12）
2. **对象类别是可操作筛选**：当前 Holders API 支持 all holders、exchange、whale、public figure、smart money 等类别、按实体聚合、金额阈值及排序，并列出部分原生代币查询限制。API 功能不自动证明前端同名控件在任意套餐中存在。[Holders API](https://docs.nansen.ai/api/token-god-mode/holders)（访问：2026-09-12）
3. **标签属于加工层**：官方 Core Concepts 说明地址标签来自研究和启发式规则，实体层将相关地址归到同一组织。这种标签帮助理解数据，但不等同于原始链上事实。[Core Concepts](https://docs.nansen.ai/getting-started/core-concepts)（访问：2026-09-12）
4. **时间窗口不等于刷新承诺**：上述教程和接口显示观察窗口；本轮未核实全站统一的刷新周期或服务承诺，不将「24h」解释成每秒更新。[Token God Mode 101](https://academy.nansen.ai/help/articles/3874203-token-god-mode-101)（访问：2026-09-12）

### 迁移建议

- 在资料行提供稳定且有释义的标签：官方事件锚点、当事人陈述、独立讨论、转载/引用；另外一组标签表达能力宣称状态，如厂商自述、独立支持、存在争议、尚未验证。
- 支持「市场 → 事件 → 公司/产品 → 原帖/讨论」的关系下钻，让同一事件关联的不同来源汇聚在一起。
- 来源身份、能力真伪、讨论热度分开。强烈争议也可能带来高互动；不能将可见热度设计成可信度勋章。
- 把观察到的账号数与跨平台人数严格区分。账号聚合只有在实体关系有证据时进行，否则保留平台与账号来源。

### 适合 / 不适合借鉴

**适合**：有解释的标签、对象详情、按来源角色与范围筛选、关系下钻。**不适合**：直接复刻 Smart Money 式精英权威标签；用「官方」证明能力属实；把推断性身份、态度或方向当作客观测量。

## 五、Artemis：共同口径下的比较，以及按指标说明刷新频率

### 已核实事实

1. **当前品牌与旧终端不是一个页面**：旧官网跳转到 about.artemis.ai，页面重点是 Analyst、研究、数据集和 Launch Terminal。旧 app 域名跳到 classic.artemis.ai；阅读器未得到其图表正文。[当前品牌页](https://about.artemis.ai/)、[classic 应用](https://classic.artemis.ai/)（访问：2026-09-12）
2. **官方 Terminal 文档把比较放在核心**：描述通过共同基本面指标比较协议、金融科技公司与上市科技企业，并按类别、应用、合约拆解活动。这里验证的是文档所述能力，不能据此断言新终端布局。[Terminal Overview](https://app.artemisanalytics.com/docs/artemis-terminal/overview)（访问：2026-09-12）
3. **数据目录说明覆盖和频率**：Supported Metrics 表列出指标解释、更新频率、是否支持日期查询，并提醒不是每条链都有每项指标。FAQ 单独解释开发活动定义、资料来源及每周三更新节奏。[Supported Metrics](https://app.artemisanalytics.com/docs/artemis-sheets/metrics/supported-metrics)、[Terminal FAQ](https://app.artemisanalytics.com/docs/artemis-terminal/faq)（访问：2026-09-12）

### 迁移建议

- 先确定可比较集合：同平台、同指标、同观察年龄、同采集范围、同方法版本。X 点赞与 Reddit score 并列显示，尚未冻结归一化前不合并。
- 同一表格允许某指标缺失；空值须注明「未取得」「未覆盖」或「未知」。数值为零与没有数据采用不同视觉和筛选状态。
- 做紧凑的指标字典：名称、准确含义、单位、输入、平台、覆盖、观察窗口、更新时间、计算版本。图表标题中直接呈现窗口和范围。
- 赛道比较可分为「累计事件」「近期讨论」「覆盖情况」几个视角，不强迫所有问题共用一个总分。

### 适合 / 不适合借鉴

**适合**：可比口径、指标字典、覆盖缺口、不同更新节奏。**不适合**：营销页展示多个数据源，就宣称本产品覆盖完整；把旧终端教程混写成当前新终端实测；在没有连续快照时画互动增速曲线。

## 六、Token Terminal：把方法论做成数据产品的一部分

### 已核实事实

1. **Explorer 有多种入口**：公开页可读到 Discover、Market sectors、Projects、Metrics、Studio 及跨对象搜索；featured chart 带主题、时间范围和指标选项。根页的产品演示不能代替 Explorer 本身。[Explorer](https://tokenterminal.com/explorer)、[品牌页](https://tokenterminal.com/)（访问：2026-09-12）
2. **图表上下文是可配置内容**：Studio Charts 文档将指标、筛选、分组和图表类型放在配置流程中；标题、描述、脚注、时间范围和粒度与图表共同保存。脚注可说明方法或链接来源。[Charts 文档](https://tokenterminal.com/docs/studio/charts)（访问：2026-09-12）
3. **方法论说明实际计算链**：2025-10-23 的官方公告将 Methodologies 分成「指标概述、数据来源、逐步计算」，并说明研究团队参与核验及免费开放。这里是产品方对其流程的声明，本轮未审计其计算系统。[Launching methodologies](https://tokenterminal.com/resources/articles/launching-methodologies)（发布：2025-10-23；访问：2026-09-12）

### 迁移建议

- 每个指标提供一个短入口，可展开：这个值是什么、用了哪些记录、如何去重和归属、怎样累计、缺什么、使用哪个版本。
- 每个图表至少包含标题、单位、观察窗口、采集范围、数据截至时间、方法版本、来源入口。导出图表仍保留这些上下文。
- 为每次指数或贡献变化提供可见账本：旧值、新值、差额、原因、相关事件、重算版本。修正是系统记录，不混成真实世界当天的能力变化。
- 分析说明与原始数据在同一页面保持联系；“打开方法”应是常见操作，而非用户怀疑数据后才能在文档中找到的补救措施。

### 适合 / 不适合借鉴

**适合**：指标与项目双入口、可共享图表上下文、来源和计算步骤、数据修订解释。**不适合**：借金融报表格式制造不具备的客观精确性；将自定义接管指数显示为已完成接管的百分比；用方法论说明掩盖尚未运行的数据管道。

## 七、对 AgentHowTo 的直接设计约束

以下均为**本项目设计建议**，不是对参考平台界面的事实描述。

| 页面 / 组件 | 建议呈现 | 必须同时解释的上下文 |
| --- | --- | --- |
| 总览首屏 | 可扫描的市场表、近期事件与讨论信号、覆盖概览 | 跟踪起点、采集范围、最新可用快照；冷启动不显示虚构总指数 |
| 市场行 | 市场名、去重事件数、平台分项信号、最近变化原因 | 变化来自新事件、计数快照、归属修订还是覆盖变化 |
| 市场详情 | 趋势、事件时间线、来源分解、原始记录 | 图表代表累计贡献还是最近窗口热度；二者分图或显式切换 |
| 比较视图 | 2–4 个市场，同一指标和窗口下比较 | 平台、指标单位、观察年龄、覆盖和方法版本一致性 |
| 事件详情 | 官方锚点、能力宣称、讨论信号、关联市场 | 公告存在不等于能力已获独立验证；互动不等于支持 |
| 指标信息层 | 单位、定义、源记录、计算说明、限制 | 缺失与零、提供方计数更新时间是否已知 |
| 变更账本 | 旧值、新值、差额、原因、版本 | 数据修正、归属修订和真实事件分开 |
| 分享 / 周报 | 固定快照、筛选摘要、来源和方法链接 | 防止新数据静默覆盖已经发布的历史结论 |

### “前卫、数据化”的可落地含义

密集而有秩序的数据结构、清楚的数字层级、可选择的指标、多对象比较和有解释的变化，可以让数据产品呈现专业终端感。视觉实验应服务这些任务：突出读者正在比较的序列、正在变化的行和当前筛选状态。

不要用装饰补足尚不存在的测量：没有快照就不画假波动，没有规范总分就不显示 87.3，没有更新时间就不标实时，没有生产事件就不填看似正式的发布榜单。冷启动也可以通过真实目录、覆盖矩阵、明确的空状态和可展开方法表现出完整的数据产品结构。

优先借鉴顺序：**DefiLlama 的总览与榜单 → Token Terminal 的指标与方法说明 → Artemis 的可比较口径 → Dune 的可复查分析与分享 → Nansen 的对象标签和关系下钻**。这一顺序是适配本项目当前数据合同的研究判断。
