## 最值得参考的地方

Tensorlake 用一组有限的图形规则反复组合：竖直条带、离散短线、方形端点、细网格、矩形边界、等宽注释。这些元素出现在品牌画面、处理流程、数据模块和网站细节中，构成持续的辨识度。

| 观察到的细节 | 在案例里的作用 | AgentHowTo 的具体映射 |
| --- | --- | --- |
| 等距竖条被切分成不同长度和颜色段 | 形成有节奏的品牌图案 | 将时间窗口画成可读取的信号条；色段只表示有定义的事件类型或状态 |
| 网格上布置细矩形、角标和短连接线 | 将处理步骤表达成工程图 | 事件 → 受影响赛道 → 状态修订；只连接有实际对应关系的实体 |
| 大号无衬线标题与等宽小标注并置 | 区分主信息、参数和操作 | 总分和赛道名称用清晰无衬线；时间、编号、版本、单位用等宽体；中文说明保持正常字号 |
| 近黑底、柔和绿、灰白与少量青蓝 | 控制层次并保留安静的背景 | 绿色用于主数据和选择反馈；辅助色按数据含义固定分配，避免每个模块各用一色 |
| 连续细线把面板划成共享的坐标系统 | 让各区块属于同一个整体 | 主图、赛道列表、更新记录共用列线和边距，表头、数值与注释对齐 |
| 代码、数字、模块名称参与主画面 | 让技术内容本身成为视觉材料 | 用事件标题、来源、实际数值与修订记录构成页面；不为制造技术感插入无关代码 |

这些是设计映射建议，不是 Tensorlake 对 AgentHowTo 的产品建议。

## 对前两版设计的修正

第一版的独立面板缺少明确主次。第二版建立了大数字、三维地形和深浅分区，但图形语言主要集中在单个主视觉，尚未延伸成完整系统。

这个案例指向下一步应先确定的规则：

1. **一个可复用的基本单元。** 采用细条与方形端点组成的信号图形，统一线宽、间距、转折和选中方式；先验证它在主图、赛道行、更新记录、空状态和分享图中的表现。
2. **主图承担真实阅读任务。** 首屏以状态与时间变化为主，条带可以表示事件在时间上的分布；能力估计仍使用有刻度的图形。品牌图案与定量图表分别标清语义。
3. **同一套界面细节。** 统一表格分隔线、标注格式、按钮边界、焦点、hover、选中、来源展开与加载状态，避免只完成首屏大图。
4. **动效表达状态变化。** 筛选时仅突出命中的信号，选择事件时连接对应赛道，展开修订时显示前后值。持续跳动、随机闪烁不能冒充实时更新。
5. **中文阅读优先。** 英文案例中的紧密大标题和很小的技术注释需要重新适配中文；控制说明不靠大量全大写英文制造密度。

## 可执行的起点

建议以“工程图式的数据界面”作为下一版研究方向：近黑画布、灰白主字、柔和绿色数据、细线分区、少量紧凑技术标注，以及贯穿图表和事件列表的条带语言。

本次在当前官网读取到的实际样式：页面背景为 `rgb(22, 23, 21)`（`#161715`）；标题的字体栈首项为 `PP Neue Montreal`，后备包含 `Inter Tight` 和系统无衬线。该桌面视口的标题字重为 500，字号约 81.9 px，负字距约 2.87 px。这是单一视口的现场观察，不是完整字号规范，也不意味着可以直接复用商业字体文件。

用户随后直接提供 Tensorlake 官网。因此将当前官网作为下一版页面细节的主要参考，HEX 案例补充品牌图形；表格比较和信息密度继续参考已调查的数据产品。将官网的“产品描述＋代码示例”转译为 AgentHowTo 的“状态判断＋可检查的数据”。

### 已观察的页面组织与交互

- **首屏：** 左侧大标题、简短说明与两个操作；右侧是可操作的示例面板。切换 Python / TypeScript / CLI 时，安装方式、主体示例和输出记录一起变化，外框与分区保持一致。这验证了界面联动，不代表本次真的创建或运行了远程 sandbox。
- **正文：** 顶部导航在已观察的滚动位置持续可见。模块使用共同边线，说明区和终端区并置；章节标题与小型技术参数分别对齐。图形和文字都服从页面的列结构。
- **数据比较：** Benchmark 区在同一模块中放置测试条件、横向比较条、数值和原始来源入口；下方说明测试设置。此处仅研究信息组织，未独立验证该公司的性能结论。
- **手机首屏：** 导航收为 Menu；两枚主要按钮变成全宽纵排；示例面板移到介绍下方。展开 Menu 后显示整屏纵向链接与操作，带逐行分隔线。
- **适配边界：** 手机端代码面板仍较高，长命令超出可见行宽。AgentHowTo 的赛道名称和关键数字应直接可读，不能沿用代码面板的裁切方式；主图高度按信息量重新设定。

### AgentHowTo 的下一版页面映射

1. **顶部导航：** 品牌、总览、赛道、事件和方法；移动端用清晰的纵向菜单。
2. **首屏左侧：** 当前能力估计、情景范围、更新时间与简短定义。保留强排版层级，收紧营销文案。
3. **首屏右侧：** 时间变化与事件信号；切换情景或赛道时，图形、摘要和明细联动。图中数值使用当前产品合同，不套用官网运行日志。
4. **下方主内容：** 赛道比较、近期修订和对应来源。借鉴 Benchmark 的“条件＋比较＋出处”结构，保留数据网站的连续阅读路径。
5. **品牌表现：** 条带与方形端点出现在主图、选中状态、章节编号和分享图中；底色、边线、字体与留白以当前官网为主要尺度。

以上为设计研究与下一版映射，尚未实施到业务页面。
