# 真实反馈、成功案例与合成数据：后训练价值的证据边界

研究日期：2026-09-13（Asia/Taipei）。状态：文献研究记录，未开展训练、数据采购、用户日志采集或系统开发。本文为 openaiwill 主动采集和分析提供依据，不把倡议改成数据交易产品，也不把社区共建、Agent 上报或认证加入首期工作。

## 判断

**真实任务及其经验证的结果有重要价值，但不能据此推出“真实成功案例在后训练中一律比合成数据更有价值”。** 本次核查的七组一手研究分别展示了真实需求、人类示范、人类偏好、合成指令、AI 偏好标签和可验证奖励的价值；有直接比较，也有混合方案。它们没有建立一个适用于所有任务、模型和预算的来源优劣排序。

对 openaiwill 而言，最直接的价值是：真实案例帮助回答 **AI 实际完成了什么工作、在什么条件下完成、谁验收、还需要多少人工**。能否进一步成为有效训练数据，则是另一个要经过授权、整理和实验验证的问题。不能把有公共观察价值直接等同于可以训练、应当共享原始日志或必然拥有商业壁垒。

## 先区分数据中的不同角色

下表是结合文献整理的阅读框架，不是新增数据库设计。

| 数据或信号 | 实际表达什么 | 可能用途 | 不能直接等同于 |
| --- | --- | --- | --- |
| 真实需求 / 用户提示 | 有人确实提出过任务及约束 | 确定任务分布、设计评测、提供训练输入 | 已完成、已验收、代表全体需求 |
| 原始交互日志 | 某人在某环境中做过什么、模型输出过什么 | 诊断、重建过程、筛选候选素材 | 正确示范、可公开数据、训练许可 |
| 人类示范 | 人工给出的答案或行动序列 | 监督微调（SFT）、模仿学习 | 唯一正确路径、真实用户已经受益 |
| 偏好标签 | 在给定标准下 A 比 B 更好 | 奖励模型、RLHF、直接偏好优化等 | 事实正确或业务完成；标签也可能由 AI 生成 |
| 人工验收 / 修改 | 结果在需求者看来是否可用、差在哪里 | 质量评估、纠错或偏好素材 | 每一步均正确、完全自主完成 |
| 环境成功验证 | 运行测试、文件状态或其他明确规则满足条件 | 评测；条件合适时作为 RL 奖励 | 用户全部隐含要求都满足、没有未检查的副作用 |
| 合成任务 / 合成轨迹 | 模型或程序生成的任务及解法 | 扩展覆盖、难度课程、SFT、蒸馏或 RL | 没有真实基础；也不自动等于正确 |
| 失败 / 中止 / 人工接管记录 | 什么条件下未达目标及其原因 | 负例、错误诊断、奖励判断、后续任务设计 | 无价值；也不应当直接作为正面示范模仿 |

同一条样本可以同时是“真实用户需求 + 模型生成轨迹 + 人工偏好 + 自动结果验证”。用一个“真实/合成”标签概括全部过程，会丢失最重要的差别。

## 一手证据

以下“已验证”表示已核实论文或作者机构公开报告及相应实验表述；不表示本项目独立复现了实验。各数字仅属于所注明的历史模型和评测设置，不代表 2026-09-13 的最新能力。

### R1. InstructGPT：真实提示需要经过示范与偏好加工

- **标题 / 作者 / 日期**：*Training language models to follow instructions with human feedback*；Long Ouyang 等，OpenAI；2022-03-04。
- **直接来源**：[论文与日期](https://arxiv.org/abs/2203.02155)；[作者机构 PDF](https://cdn.openai.com/papers/Training_language_models_to_follow_instructions_with_human_feedback.pdf)。重点：§3、§5.2、附录 A.2。
- **已验证事实**：流程结合用户提示和标注员编写的提示，用人类示范做 SFT、用回答排序训练奖励模型，再做强化学习。在其测试分布上，1.3B InstructGPT 的输出优于 175B GPT-3，按人工偏好衡量。
- **支持**：真实需求可以提供重要的任务分布；示范和比较标签能把需求转为可学习监督。
- **不支持与局限**：论文明确只使用经过告知的 API Playground 提示，没有使用客户生产 API 数据；也不是直接收集用户已验收的成功案例。标注员偏好有分歧和人群边界。该实验不隔离“真实来源”相对于合成来源的单独增益。

### R2. OSWorld：把真实场景变成可运行、可检查的任务

- **标题 / 作者 / 日期**：*OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments*；Tianbao Xie 等；首次提交 2024-04-11；本次阅读 v2。
- **直接来源**：[论文](https://arxiv.org/abs/2404.07972)；[全文](https://arxiv.org/html/2404.07972v2)。重点：§2、§3.2。
- **已验证事实**：369 个桌面/网页任务配有初始状态和执行式验收脚本。任务来自作者及论坛、教程等，也包含作者组合构造的场景；并非一整套未经处理的真实用户日志。论文指出，只比对固定示范路径会误判其他正确做法。
- **支持**：真实使用线索经过环境还原和验收设计，才能变成可复核的完成证据。任务来源真实与任务经过人工构造并不冲突。
- **不支持与局限**：这是评测与交互环境工作，没有证明用这些案例训练一定胜过合成数据。可复现任务仍是经过选择的样本，验收脚本只覆盖写入规则的目标。

### R3. SWE-Lancer：真实已付费任务可用于经济能力评测

- **标题 / 作者 / 日期**：*SWE-Lancer: Can Frontier LLMs Earn $1 Million from Real-World Freelance Software Engineering?*；Samuel Miserendino 等，OpenAI；论文 2025-02-17，官方发布 2025-02-18。
- **直接来源**：[论文](https://arxiv.org/abs/2502.12115)；[全文 v1](https://arxiv.org/html/2502.12115v1)；[官方发布及更新说明](https://openai.com/index/swe-lancer/)。重点：数据构建、§4。
- **已验证事实**：研究从 Upwork 上实际付费完成的 Expensify 工程任务构建基准，覆盖超过 1,400 个任务及约 100 万美元历史报酬。代码任务采用经工程师多次核查的端到端测试，管理任务参考原工程经理的选择。
- **支持**：真实完成案例可以提供任务、上下文、验收和历史价值依据，而不只是一句“用户觉得不错”。
- **不支持与局限**：该工作是评测，不是成功案例训练消融。来源集中于单一代码库；历史报酬不能直接当作 AI 当前收入或企业节省金额。官方页面注明 2025 年 7 月数据更新，跨版本成绩需另行对齐。

### R4. RLAIF vs. RLHF：AI 偏好标签有直接比较证据

- **标题 / 作者 / 日期**：*RLAIF vs. RLHF: Scaling Reinforcement Learning from Human Feedback with AI Feedback*；Harrison Lee 等，Google / Google DeepMind；首次提交 2023-09-01；本次阅读 v3（2024-09-03，ICML 2024）。
- **直接来源**：[论文与版本](https://arxiv.org/abs/2309.00267)；[全文](https://arxiv.org/html/2309.00267v3)。重点：§3、§4.1、Table 1。
- **已验证事实**：在摘要和有帮助的对话实验中，RLAIF 对 RLHF 的人工偏好胜率为 50% 和 52%，没有显著偏离五五开；无害性任务也未显示人类反馈必然占优。实验使用人类已有任务/候选回答数据，替换的是偏好标签来源。
- **支持**：这是反对“人工反馈必然比 AI 反馈有效”的直接证据；来源须按任务、输出、标签分别说明。
- **不支持与局限**：不等于完全脱离人类数据，也不比较生产现场成功轨迹。研究使用特定 PaLM 2 模型和三个任务，不能推成所有领域的人类专家标签均可替代。

### R5. Self-Instruct：合成指令可以产生实质训练收益

- **标题 / 作者 / 日期**：*Self-Instruct: Aligning Language Models with Self-Generated Instructions*；Yizhong Wang 等；首次提交 2022-12-20，ACL 2023；本次阅读 v2。
- **直接来源**：[论文](https://arxiv.org/abs/2212.10560)；[全文](https://arxiv.org/html/2212.10560v2)。重点：§2、Table 3、§4.4、局限。
- **已验证事实**：从 175 个人工种子任务出发，模型生成指令及输入输出，过滤后微调 GPT-3；在 SuperNI 未见任务上，ROUGE-L 从 6.8 提升到 39.9，接近 InstructGPT-001 的 40.8。这是 ROUGE-L 分数，不是业务成功率。
- **支持**：合成扩展在特定设置下有可测收益；高质量人工种子与大规模合成并非二选一。
- **不支持与局限**：人工种子和预训练知识依然存在，生成样本也有噪声。与 InstructGPT 的对照不是相同数据量、预算和训练过程下只改变来源的严格消融。

### R6. DeepSeek-R1：可验证奖励能减少对逐条人工示范的依赖

- **标题 / 作者 / 日期**：*DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning*；DeepSeek-AI；2025-01-22；本次阅读 v1。
- **直接来源**：[论文](https://arxiv.org/abs/2501.12948)；[全文](https://arxiv.org/html/2501.12948v1)。重点：§2.2.2、§2.2.4、§2.3。
- **已验证事实**：R1-Zero 从已预训练的基础模型开始，不先做 SFT，以数学答案和代码测试等规则奖励进行 RL；报告 AIME 2024 pass@1 从 15.6% 到 71.0%。后续 R1 又使用冷启动数据、生成后筛选的样本及面向偏好的训练。
- **支持**：明确可验证的目标能驱动模型自行生成、试验和学习，不必给每一步配人工成功示范。
- **不支持与局限**：不是从零知识学习，也不能把“无先行 SFT”写成“无人类数据”。数学/代码校验不涵盖所有开放业务目标；R1-Zero 的可读性问题也推动了混合流程。

### R7. WebRL：人类演示、合成课程、成功与失败具有不同作用

- **标题 / 作者 / 日期**：*WebRL: Training LLM Web Agents via Self-Evolving Online Curriculum Reinforcement Learning*；Zehan Qi 等；首次提交 2024-11-04；本次阅读 v3（2025-01-27，ICLR 2025）。
- **直接来源**：[论文](https://arxiv.org/abs/2411.02337)；[全文](https://arxiv.org/html/2411.02337v3)。重点：§3.1、Table 1、附录 B / Algorithm 1。
- **已验证事实**：先以人类演示做 SFT，再从失败任务生成新指令、在网页环境交互并训练；成功轨迹进入回放，失败也用于下一轮课程。Llama-3.1-8B 在 WebArena-Lite 上由 SFT 的 20.6% 提升至 WebRL 的 42.4%。
- **支持**：混合方案可超过仅模仿示范；失败有训练用途，成功轨迹适合某些回放用途。
- **不支持与局限**：这是整个方法的增益，含额外数据和 RL，不是只控制来源的对照。新生成任务由训练过的结果奖励模型判断，并非每条都由确定性脚本验证；不能把模型判断当无误的真实验收。

## 直接比较能回答到哪里

| 证据 | 比较的对象 | 可得结论 | 尚不能回答 |
| --- | --- | --- | --- |
| R4：RLAIF vs. RLHF | 特定任务上人类与 AI 偏好标签训练出的策略 | 人类标签并不普遍占优，AI 标签可在这些设置下接近或超过 | 真实生产成功案例是否更有价值 |
| R5：Self-Instruct | 原 GPT-3、合成指令微调及其他模型/数据方案 | 合成指令训练确有收益 | 相同预算下真实案例与合成案例的纯来源效应 |
| R7：WebRL | 人类示范 SFT 与在其上增加课程、交互和 RL | 更多可学习反馈能超过仅模仿，失败有用途 | 收益有多少单独来自真实来源或合成来源 |
| R2 / R3 | 真实场景导出的评测任务 | 能检验任务完成及其局限 | 将评测案例用于训练的净增益 |

**本次所核查的七组材料中，没有找到支持“在相同任务分布、样本数和计算预算下，真实用户成功案例对各种后训练普遍优于合成案例”的通用实验。** 这不是断言不存在相关研究，而是当前证据不足以支持这句话。对“更有价值”还需先指定是训练收益、发现真实需求、衡量能力、稀缺性、成本还是可获得的授权。

## 对 openaiwill 的项目推论

以下是由上述研究启发的推论，尚未经本项目实验验证。

1. **真实案例首先校准观察目标。** 相比只看模型发布和考试分数，实际工作中的任务、约束、人工接管及结果有助于解释“接管了多少工作”。这是倡议主动采集和分析的直接理由，无需预设一个训练数据交易产品。
2. **更有价值的单位可能是经核验的任务记录，而不是原始日志。** 阅读案例时应追问任务要求、模型及工具版本、初始条件、尝试次数、人工参与、交付物、验收者/规则、验证时间和局限。缺少这些信息的“成功”自述仍是线索。
3. **“成功”至少有不同含义。** 用户满意、交付物被采用、测试通过、业务结果达成以及无需人工接管不能混写。一个局部步骤通过也不等于完整工作完成。
4. **只收成功会丢失边界。** 必须理解失败、返工、中止和未获结果的情况，才能评估可靠性；没有尝试总数的成功案例数量不宜直接换算成成功率。这是统计判断与项目方法建议，不是上述论文给出的生产评分公式。
5. **合成数据适合扩展检验，不能冒充真实采用。** 可以从真实问题生成变体、课程和测试，但应保留来源及验证方式；合成任务的成功不能记录成真实用户已经采用。
6. **公开分析、共享原始材料和允许训练是不同权限。** 可公开引用的案例不自动允许重新分发完整过程、企业文件或个人数据，也不自动许可第三方训练。这里仅给出研究与项目边界，不对具体数据授权作法律判断。

## 可用于白皮书的表述

> 真实使用的价值，不只是留下更多对话，而是揭示人们实际需要完成什么、AI 在哪些条件下有效，以及结果是否得到验证。我们主动采集和分析这些证据，让 AI 独立完成工作的进度更透明、更可信。真实任务、人工反馈、合成数据和环境验证各有作用；我们重视可追溯、可解释和可复核的结果，不预设某一种数据来源永远更好。

这段表述是项目立场与研究推论，不是实验证明的训练收益承诺。社区可补充案例和更正，但参与不是读者获得价值的前提。

## 本轮核查范围

- 已检查上述七组论文/作者机构报告的相关方法、结果和局限；只保存摘要与链接，未保存长篇原文。
- 未复现训练实验；没有用 2022—2025 年历史分数代表今天的模型能力。
- 未证明任何厂商从特定用户行为获取了某种未公开的训练数据；未读取本地凭证或私人日志。
- 后续若要评估训练价值，应另立受控实验问题，包括来源、质量、样本量、任务难度、算法、计算成本与独立测试集。本轮不启动该实验，也不扩展首期实现范围。
