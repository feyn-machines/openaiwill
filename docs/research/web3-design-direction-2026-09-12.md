## 1. 建议采用的方向

**把 AgentHowTo 做成 AI 进度观测台：深色数据终端作为主体，像素光场作为识别元素，事件信号、趋势、赛道和证据形成连续的阅读路径。**

参考组合：

- **ThreeUI** 提供像素、空间层次、精密刻度和局部动效的视觉语言。
- **DefiLlama** 提供高密度总览、可排序榜单和维度切换的工作方式。
- **Token Terminal** 提供图表、解释材料、方法论和可比指标的组织方式。
- **Nansen** 提供深色底与薄荷绿信号色的品牌参考。
- **Dune / Artemis** 补充图表参数、研究工作台和数据更新时间的设计思路。

这些是对实际页面与官方资料的设计归纳，不表示沿用它们的商标、源码或数据。来源调查见[Web3 平台模式研究](web3-data-platform-patterns-2026-09-12.md)。用户补充的 X 原帖包含 8 个灵感网站，已逐项核对并整理为[设计灵感来源清单](design-inspiration-library-2026-09-12.md)；Layers、60fps、Navbar Gallery 与 Supahero 分别补充空间视觉、微交互、导航和首屏构图。

## 2. 从项目当前状态出发

本次读取了 `README.md`、`CONTEXT.md`、`src/app/page.tsx`、`src/app/layout.tsx`、`src/app/globals.css`、`src/components/market-grid.tsx` 和[接管进度框架](../data/takeover-progress-framework-v1.md)。

现有视觉是米白底、深绿文字、荧光浅绿点缀、超大标题、Georgia 斜体与赛道卡片。首页围绕创业想法的介绍和浏览入口组织，尚没有指数、趋势、覆盖与变动记录。

此前读取的 v0.2 产品文档把核心推进为：**AI 接管进程指数（事件与社区信号）、累计事件贡献、最近窗口热度、指标覆盖、变化原因**。公开品牌使用 AgentHowTo；仓库仍叫 WillAI。本段保留为早期研究快照，当前产品方向见 v0.3。

当时的 **v0.2** 不再要求 A/R/U/D 四级人工评分；归一化和权重尚未冻结，先展示可取得的原始信号。后续 **v0.3** 新增具有固定分母的 100 分能力状态估计；本文下文“累计信号没有自然满分”的限制仅适用于原始事件与社区信号，不能据此否定 v0.3 的加权能力总分。

需要完成的设计转变：

| 目前的呈现 | 目标呈现 | 对用户的作用 |
| --- | --- | --- |
| 大幅营销标题占据首屏 | 短标题＋事件信号＋趋势＋覆盖 | 打开即可知道研究对象和当前状态 |
| 卡片逐一介绍赛道 | 表格比较赛道，详情解释差异 | 在同一视线内找到变化和未知项 |
| 官方更新作为独立新闻入口 | 变化关联事件、赛道和来源 | 解释新事件、互动更新和数据修正 |
| 配色主要表达品牌 | 品牌色、数值强度、状态色分别定义 | 用户能稳定解读颜色 |
| 视觉上容易延伸成展示型网站 | 可阅读、可比较、可追溯的数据工作台 | 支持持续使用 |

评分引擎、数据库、持续采集和生产评分尚未接通。**当前上线形态必须设计“未建立基线”，不能为了画面饱满填写真实指数。** 本研究中的有数值画面只允许出现在明确标注的设计演示中。

## 4. ThreeUI：逐个组件如何用到本产品

### 4.1 最值得优先研究的元素

| 组件与直接链接 | 本次可核验内容 | 在 AgentHowTo 的用途 | 具体限制 |
| --- | --- | --- | --- |
| [Predictive Arc](https://threeui.com/backgrounds/predictive-arc) | 实看紫色像素弧与局部亮核；页面提供多个变体 | 指数总览的品牌光场，或周报封面构图 | 装饰不承担计分；不用形状暗示未来预测 |
| [Data Pixel Arc](https://threeui.com/backgrounds/predictive-arc/data-pixel) | 已打开变体；官方说明为翡翠色像素地平线 | 主推方向的薄荷／青绿像素母题 | 本次不把说明中的“呼吸”当作已做持续动效测评 |
| [Structure Flow / Data Field](https://threeui.com/three-js/structure-flow/data-field) | 实看细线、深色空间结构；官方将其归为数据网络视觉 | 关系图页面的空间构图参考、品牌背景 | 若变为知识图谱，节点和连线必须对应真实实体关系；生成的装饰网络不能假装证据图 |
| [Diagnostics Panel](https://threeui.com/ui-elements/diagnostics-panel) | 官方列出层叠平面、节点方块、流动网格三个变体；运行方式标为 Canvas 2D | 声量、互动、账号和社区分布的概念示意 | 本次首个预览观察时未完整呈现图形，适用性判断依据官方变体说明；不能代替原始指标对比 |
| [Performance Gauges](https://threeui.com/css/performance-gauges) | 实看橙色精密仪表；官方标为 DOM＋CSS | 借鉴刻度精度、数值层级、局部材质 | 只取数字层级和刻度美感；累计信号没有自然满分，不用闭合仪表假装完成度，也不自动扫针伪装测量 |
| [Aureon Markets](https://threeui.com/hero/aureon-markets) | Pro 公开预览可见蓝紫空间背景和玻璃式表面；官方描述为交易 Hero | 高表现力备选方向，适合专题和品牌页 | 公开预览有 Pro 覆盖层，未核验拖拽或完整交互；采购和源码复用另行核实授权 |
| [NODAL](https://threeui.com/landing-pages/nodal-landing-page) | 已读公开产品故事说明 | 借鉴“精密仪器”的概念和有依据的结构拆解 | 本次没有据其受遮挡预览推断完整视觉；镜头产品的滚动叙事不作为数据首页结构 |

**ThreeUI 的作用是建立辨识度。** 数据工作仍由平面的数值、轴线、表格、标签和来源面板承担。这样前卫感能贯穿产品，同时保留数据阅读效率。

### 4.2 视觉层与数据层的分工

- 品牌层：一个像素弧场或结构场，放在总览指数区的侧后方。文字后方保留安静区域，亮核避开关键数字。
- 数据层：横向比较、趋势曲线、信号分项和变动记录，使用实色背景。
- 证据层：以正文、引用、时间、指标旧值／新值和可用性条件为主；弱化动效，增加阅读空间。
- 装饰可以没有坐标，但必须让人一眼识别为背景；凡呈现数值的图表都应标注单位、时间和范围。

## 5. 三套候选风格

以下为本研究提出的设计选择，颜色值不是从参考网站提取的官方品牌色。

| 方向 | A：信号观测台（主推） | B：精密数据仪器 | C：光谱市场图 |
| --- | --- | --- | --- |
| 气质 | 前沿、冷静、持续观测 | 工业、精确、结构清晰 | 更强的数字空间感和品牌表现 |
| 底色 | 近黑与少量冷绿层次 | 石墨黑、钢灰 | 午夜蓝、靛蓝 |
| 主色 | 电子薄荷 `#6BE7CF` | 仪器橙 `#FFBC7A` | 光谱紫 `#BAA0FF` |
| 辅助识别 | 酸性浅黄绿，只用于小面积强调 | 米白数字、橙色刻度 | 青色数据线、紫色光场 |
| 母题 | 像素弧场、微点阵、分段刻度 | 紧凑面板、坐标编号、结构剖面 | 弧形空间、折射边缘、粒子层 |
| 页面构成 | 高密度表格＋一处视觉锚点 | 密度最高、几乎全为数据和刻度 | 总览表现力强，详情回归实色面板 |
| 参考角色 | ThreeUI Arc＋DefiLlama＋Nansen | Gauges / Diagnostics＋Token Terminal | Aureon Markets＋Predictive Arc |
| 代价 | 需要控制光场亮度和数据语义 | 品牌情绪偏冷，容易过于工具化 | 较容易喧宾夺主，开发与性能约束更多 |
| 建议 | 主站采用 | 可作为数据密集模式或备选 | 专题／发布页适用，也可作为第二轮视觉实验 |

主推 A 的理由：接管指数是一个需要反复访问的观察产品。用户第一次打开能感到前沿，之后每天使用仍能快速比较。B 是可靠的紧凑替代；C 更适合需要强品牌表现的场景。

## 6. 主推方向的视觉规范

### 6.1 颜色、表面和字形

| Token / 元素 | 建议值 | 使用规则 |
| --- | --- | --- |
| 页面底色 | `#080D0F` | 近黑，减少纯黑与纯白的刺眼反差 |
| 主面板 | `#10181C` | 所有表格和证据正文使用不透明底色 |
| 悬浮／选中层 | `#18252A` | 可点击行、菜单和局部选择 |
| 分隔线 | `#2A3B42` | 用于轻分组；关键输入和焦点需要更强边界 |
| 主文字 | `#EAF1F2` | 标题、数值、重要状态 |
| 次文字 | `#A0B2B9` | 时间、单位、说明，仍保持可读 |
| 品牌／当前选择 | `#6BE7CF` | 导航选中、主要序列、关键交互 |
| 信号增加 | `#8DBBFF`＋“↑ 增加” | 只描述该项计数或贡献变化；争议升温也可能增加 |
| 信号减少 | `#FFBD8A`＋“↓ 减少” | 只描述对应指标；不直接解释为能力退步 |
| 修正／方法调整 | `#C3ADFF`＋明确文字 | 与新事件和互动更新分开 |
| 未知 | 灰色斜线／`— 未取得` | 不用红色，不画成 0；未查询与字段缺失分别说明 |
| 错误 | 专用红色与错误文本 | 仅用于加载失败、验证失败等产品状态 |

英文标题建议探索 Space Grotesk；界面正文优先系统无衬线；中英文数字、时间和差值可用 IBM Plex Mono / 系统等宽字体，并开启等宽数字。中文使用系统中文无衬线回退。字体是候选，首次实现应核对实际字重、中文混排和字体授权，避免为外形增加不必要的加载量。

标题建议 28–36px，核心事件计数 56–72px，导航／表格 13–14px，说明 12–13px；正文行高 1.5–1.7。大数字后紧跟实际单位，例如“个去重事件”“条关联帖子”；未来累计贡献使用方法定义的单位，不附加 `/100`，不把所有标签都写成微小的全大写。

8px 间距体系；面板圆角 8–12px，控件圆角 4–6px。轻微内亮边可以用于总指数面板，普通行以分隔线和底色变化建立层级。图标使用同一套细线图标，不混入表情和拟物小图。

### 6.2 网格与信息密度

- 桌面：顶部 56px 导航，左侧约 176–192px 栏；主要内容随视口延展，上限约 1600px。
- 主内容用 12 栏。首排“事件信号与覆盖”占 4 栏，“趋势与变化标注”占 8 栏；次排“赛道比较”占 8 栏，“最近变化”占 4 栏。
- 1440×900 设计目标：首屏看见事件信号、单位、覆盖、方法版本、趋势，以及至少 4–6 行赛道数据。该目标尚未在业务页面验收。
- 常规表格行高 44–48px，紧凑模式可到 36–40px；数字右对齐、单位同列、名称左对齐。
- 搜索和全局时间筛选属于顶部工作台；单个图的序列与指标切换位于图内，避免重复控制。
- 当前原型仅有少量页面，不把未来功能全部做成可点击的空导航。

### 6.3 前卫感的组成

将视觉预算集中到一个明确母题：**由规则像素和局部发光组成的弧形场**。可使用静态纹理建立第一帧，以可停止的轻微运动增强空间感。表格、正文和数字保持稳定。

边缘刻度、精确数字和大面积深色留白提供“观测仪器”气质；表格的密度、曲线的节奏和局部状态高亮提供“数据化”。不要靠满屏发光边框或每块面板都漂浮来完成风格。

## 7. 页面信息架构（v0.2）

### 7.1 总览

阅读顺序：观察到什么 → 哪些赛道在变 → 哪些事件引起反应 → 原始材料和计数来自哪里。

1. 顶部：AgentHowTo、总览／赛道／事件／方法论、搜索、日期范围。
2. 信号区：跟踪起点以来的去重事件数、窗口内关联帖子数、查询范围和数据截至时间。指数归一化尚未建立时直接标注“采样期”。
3. 趋势区：累计事件／贡献与最近窗口热度分别显示，不共用无说明的轴。只画有快照的时间段，方法版本和采集范围改变处标注。
4. 赛道表：赛道、去重事件、窗口声量、平台互动分项、账号／社区分布、来源与覆盖。冻结评分规则后再加入事件贡献列。
5. 变动栏：新事件、已知事件互动更新、去重／归属修正、历史补录、采集范围与方法调整；逐项解释变化。
6. 方法说明、查询覆盖和周报入口靠近数据；主导位置仍属于数据。

### 7.2 赛道详情

上方显示累计事件与近期信号；中部是去重事件表。选择事件后，显示相关帖子、X 互动分项、Reddit score／评论数、发声账号和社区分布。每项带平台、观察时间窗、查询范围、提供方和计数新鲜度。

同一事件的多标签用于检索，不能在总量中重复计数；未来分给多个赛道的贡献份额应合计为 1。不同平台的互动分开呈现，不让用户误以为 X 点赞与 Reddit score 是同一单位。

### 7.3 事件与证据详情

数值可沿下面的路径追溯：

**信号分项 → 关联帖子与去重规则 → 计数快照 → 原始链接 → 事件锚点。**

未来启用贡献分后，再展示“旧贡献 → 新贡献 → 本次差额 → 归一化版本与分配份额”。

详情明确分出三个区：①事件发生依据；②能力宣称及核验状态；③社区反应和计数。传播热度不决定宣称的真假，质疑也会产生互动。公告日期、可用日期、采集日期、提供方计数更新时间分别命名。

### 7.4 图谱

从一个事件展开到产品／公司、相关帖子、参与社区和赛道。默认只显示必要关系，连线具有明确语义。可以借鉴 ThreeUI 的空间构图，但实体名称和边必须可读。提供同内容的列表视图，移动端优先列表。

### 7.5 当前冷启动首页

指数：`采样期 · 归一化规则尚未建立`；真实信号没有接通时计数为 `—`，写明“尚未取得”，不填演示值。趋势在首个有效快照后启动，不倒填历史。

赛道展示现有真实目录并标注采集状态；范围展示实际启用的账号、社区、时间窗及缺口。现有 20 个赛道是目录，不等于完成评估的分母；51 个已启用账号的登记记录也不表示采集管线已经运行。

设计演示可放虚构计数，必须整屏明确标为“设计演示 · 虚构数据”，并在数值区域保留标识，避免截图脱离上下文造成误读。

## 8. 图表选择与数据语义

| 读者的问题 | 首选图形 | 不误导的条件 |
| --- | --- | --- |
| 从开始跟踪以来积累多少？ | 数字＋累计曲线 | 用事件个数或已定义的贡献单位，不使用完成百分比 |
| 近期哪里更活跃？ | 窗口柱图／折线 | 标明平台、窗口、指标、范围与截断情况 |
| 各赛道有哪些差异？ | 排序表＋横向条形 | 比较同平台、同年龄窗口、同范围；多标签不重复累加 |
| 信号具体由什么组成？ | 帖子、互动、账号和社区分项 | X 与 Reddit 保留各自原值；不是全网人数或支持人数 |
| 累计贡献为何变化？ | 差值条形／瀑布图＋账本 | 评分冻结后才启用；新增和修正分开；按新旧差额更新 |
| 为什么这件事值得关注？ | 事件详情和局部关系图 | 原始事实、宣称核验、社交反应分别展示 |

热力图可以编码同尺度的窗口声量，注明颜色与单位；格子面积保持等权，避免暗示市场规模。首页避免把五种不同单位塞进一张雷达图。K 线需要明确开／高／低／收语义，本项目没有理由为了交易感而使用。

“↑ 热度”只表示已观察信号上升，不代表 AI 能力进步。事故、撤回、质疑也可能有高热度。真实 0、字段未知、未查询、采集失败、数据过期、暂无可比快照分别设计；尚未验证重复刷新能力时，不显示互动增速或实时徽标。

## 9. 动效、响应式与实施约束

### 动效建议

- 表格 hover、筛选反馈：120–180ms；抽屉／面板：180–240ms。这些是设计目标，尚未测量。
- 数据刷新只强调发生变化的单元格，不让所有数字重新从零开始计数。
- 装饰层如有持续运动，应有暂停方式；离屏和后台停止。`prefers-reduced-motion` 下使用静态结果。
- 数据为空或加载失败时不继续闪烁“LIVE”。更新时间来自真实采集或核验记录。

### 移动端

到平板尺寸，主图与指数上下排列，次要侧栏折叠。390px 下默认看到事件信号、覆盖、变化、前几条赛道；表格只保留名称、事件数和窗口声量，证据／覆盖详情可展开。必要的宽表仅在表格区域横滚。

触摸目标以约 44px 为设计目标；正文对比、焦点可见和不用颜色单独编码状态纳入验收。长中文标签不可靠无限缩字解决。

### 性能和技术选择

现有 Next.js／React／plain CSS 足以完成数据主体。先用 CSS 和 SVG 建立视觉规范与静态光场，再评估是否引入 Canvas／WebGL。ThreeUI 官方不同组件本身也有 DOM＋CSS、Canvas 2D 和 Three.js 等不同运行方式；不能把整个库视为同一成本。

若采用 WebGL，只在需要的区域延后加载，先给静态第一帧；低性能、减少动态效果、上下文丢失时回到静态。普通表格和文字不依赖 WebGL 初始化。

不得根据 ThreeUI 页面展示的“code KB”直接预测生产包体积，也不得据演示 FPS 承诺用户设备帧率。首次实施需核对实际依赖、SSR 边界、导出方式与授权；本次仅研究公开资料，未安装包、购买 Pro 或复制模板源码。

## 10. 后续设计验证顺序

1. 用当前真实无评分状态完成总览、赛道详情和证据详情三屏；同时准备清晰标为演示的有数据状态，验证不同密度。
2. 以 A 方向完成配色、字体、表格、信号分项和一个像素母题；对比 B／C 的视觉样本，确定品牌表现强度。
3. 验证 1440、1024、768、390px，长中文、未知、0 计数、信号减少、方法变更和加载失败。
4. 再对接事件快照和贡献账本；视觉不应反过来要求编造历史数据。
5. 有真实业务代码修改后，按项目要求运行 `pnpm lint`、`pnpm typecheck`、`pnpm build`；数据和图表另按口径验证。

本次交付为研究和可讨论的视觉样本，不代表业务页面已改版，也不代表产品数据已经接通。
